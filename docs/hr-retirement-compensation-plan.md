# HR 퇴직 효력·임금안 연계 기획 및 평가

> 2026-09-28 개정(xdnode-management D2-개정·D2-a): 전자결재가 없어졌다. 퇴직 요청은 편집 권한자가 등록하는 즉시 반영되어 `IN_PROGRESS`로 시작한다. 결재 시절에 제출돼 남은 `SUBMITTED` 요청은 화면의 승인/반려 버튼으로 처리한다.

## 1. 문제 정의

- (당시) 전자결재가 승인되고 퇴직일이 지났어도 체크리스트와 정산이 모두 끝나지 않으면 직원 상태가 `퇴직 예정`에 머물렀다.
- 이 상태 때문에 조직관리와 재직 명부에서 퇴직자가 계속 보였다.
- 임금 계산 대상과 급여 기준값이 HR 인사기록과 분리되어 브라우저 임시 명부에 의존했다.
- 임금 계산 결과를 확정해도 HR 급여관리의 월별 공식 기록으로 연결되는 통제된 경로가 없었다.

## 2. 1차 기획

1. 등록된(즉시 반영) 퇴직 요청은 퇴직일 도래 시 체크리스트 완료 여부와 무관하게 고용상태를 `퇴직`으로 전환한다.
2. 후속 절차가 미완료이면 요청 상태를 `EFFECTIVE`로 두고 입·퇴사 관리에서 계속 관리한다.
3. 체크리스트와 정산까지 끝나면 `COMPLETED`로 전환한다.
4. 인사기록카드에 기본급·식대·육아수당·자가운전수당을 기준정보로 저장한다.
5. 월 임금안은 HR 기준정보를 스냅샷으로 불러와 서버에 초안으로 저장한다.
6. 확정 시 같은 월 HR 급여기록을 임금안으로 교체하고, 수정하기 후 재확정할 때 다시 덮어쓴다.

## 3. 평가와 기획 개선

### 평가에서 발견한 위험

- 퇴직 효력과 절차 완료를 하나의 상태로 유지하면 조직·권한·급여 대상이 잘못 남는다.
- 확정 임금안을 브라우저 저장소에 두면 다른 PC와 사용자가 같은 공식 기록을 보지 못한다.
- 확정 후 HR 급여 검토·승인·마감이 시작된 상태에서 임금안을 자유롭게 다시 열면 승인 근거가 바뀐다.
- 클라이언트가 보낸 지급총액을 검증하지 않으면 세부 항목과 총액이 달라질 수 있다.

### 개선된 통제

- 고용상태와 오프보딩 절차상태를 분리한다.
- 월별 `hr_compensation_runs`와 직원별 스냅샷 `hr_compensation_lines`를 서버의 단일 진실원으로 사용한다.
- 버전 번호로 동시수정 충돌을 차단한다.
- 서버가 세부 지급항목 합계와 지급총액 일치를 검증한다.
- HR 급여관리가 `REVIEW`, `APPROVED`, `LOCKED`이면 임금안 재개방을 차단하고 급여관리에서 먼저 작성 중으로 되돌리도록 한다.
- 확정은 같은 급여월의 HR 급여행을 교체하되 다른 월과 과거 원본은 건드리지 않는다.
- 모든 작성·저장·확정·재개방은 ERP 감사로그에 남긴다.

## 4. 상태 모델

### 퇴직

`IN_PROGRESS → READY`는 퇴직일 전 절차 상태다(등록 즉시 `IN_PROGRESS`. `SUBMITTED`는 결재 시절의 레거시 대기 상태로, 승인하면 `IN_PROGRESS`, 반려하면 `REJECTED`). 퇴직일이 오면 미완료 절차가 있어도 `EFFECTIVE`가 되고 직원은 `퇴직`으로 바뀐다. 모든 체크리스트와 정산이 끝나면 `COMPLETED`가 된다.

### 임금안

`없음 → DRAFT → CONFIRMED → DRAFT → CONFIRMED` 순환을 허용한다. `CONFIRMED`는 HR 급여관리 반영 완료를 뜻하고, HR 급여가 검토 이상이면 재개방하지 않는다.

## 5. 구축 범위

- 퇴직 효력 자동 반영 함수와 HR 운영 조회 경로
- 입·퇴사 관리의 퇴직자·후속절차 영역
- 인사기록카드의 네 가지 급여 기준값
- 월별 임금안 생성·저장·확정·수정 API와 화면
- HR 급여관리 월별 기록 덮어쓰기
- 마이그레이션, 계산 단위 테스트, 원장 제약 테스트, 소스 통제 회귀 테스트

## 6. 검증 기준

- 등록된 퇴직일이 지나면 체크리스트가 남아도 직원 상태가 퇴직이고 조직·재직 명부에서 제외된다.
- 같은 요청은 입·퇴사 관리의 퇴직자 관리에서 계속 확인할 수 있다.
- HR 급여 기준값을 저장 후 새로고침해도 유지된다.
- 월 임금 작성 시 대상월에 재직기간이 겹치는 직원만 포함되며 퇴직일도 불러온다.
- 확정 시 HR 급여관리에서 같은 월과 같은 인원의 결과가 보인다.
- 수정·재확정 시 같은 월 기록이 중복되지 않고 교체된다.
- 빌드와 전체 자동화 테스트가 모두 통과해야 배포한다.
