# HR 및 임금계산 전수 점검 — 2026-09-21

> 후속 처리: 사용자 지정 범위에 따라 UI 수정 및 로컬 AI 연동 재검증을 완료했다. 최신 결과는 [후속 보고서](hr-ui-local-integration-2026-09-21.md)에 기록했다. 아래 내용은 최초 점검 시점의 상태다.

## 결론

메뉴 전체를 대상으로 화면 진입, API 권한, 계산 및 주요 업무 흐름을 점검했다. 확인된 데이터 보존·동시 저장·초기 스키마·엑셀 오류를 수정했고, 빌드와 전체 테스트 383개가 통과했다. 다만 인센티브→임금 반영의 기간/계산 기준, 기존 UI 정적 검사 오류, 미구현 설정 화면 및 외부 AI 실연동은 남아 있다. 따라서 **모든 기능의 운영 검증이 끝났다는 판정은 아니다.**

이번 보고서는 이전 `hr-compensation-audit-2026-09-21.md` 이후의 추가 점검 결과다. 작업 시작 전부터 존재한 변경 사항은 유지했으며, 운영 배포·커밋은 하지 않았다.

## 검사 방법과 범위

- HR 20개 API 라우트: GET이 있는 19개 라우트의 신규 DB/마이그레이션 DB 초기 호출, 비로그인 차단, 29개 쓰기 요청의 VIEWER 차단.
- 문서, 결재 설정, 영업 인센티브 연결 API도 포함.
- 실제 TypeScript 라우트·인증·SQL을 메모리 SQLite에서 실행. Cloudflare D1 인터페이스, 로그인 입력, R2만 테스트용으로 대체했다. D1 batch에 대응하는 트랜잭션과 저장 직전 경쟁 상황을 재현했다.
- API 통합 검사 111개, 브라우저 인센티브 순수 계산 검사 4개 추가. 전체 383개에는 기존 계산 검사와 소스 구조 검사도 포함된다. **383개 모두가 브라우저 E2E 검사는 아니다.**
- 실제 브라우저에서는 목록·상세·설정 화면과 엑셀 다운로드를 확인했다. 실제 직원의 입사·퇴직·급여 확정·삭제를 검사 목적으로 실행하지 않았다. 쓰기 시나리오는 격리 DB/R2에서 실행했다.
- 초기 GET 검사는 HTTP 500 이상이 발생하지 않는 스키마 안정성 검사이며, 모든 빈 데이터 요청이 200이어야 한다는 검사는 아니다.

## 이번에 수정한 오류

| 문제 | 수정 및 검증 |
|---|---|
| 신규 DB에서 다른 화면을 먼저 열어야만 동작하는 API | 직원·임금안 공통 스키마 보강. 선택 모듈 테이블이 없으면 빈 집계를 반환하되 실제 SQL 오류는 숨기지 않음. 신규/마이그레이션/병렬 초기화 검사 통과 |
| 직원 일부 항목 저장 시 기존 연락처·입사일·이력 등이 지워질 수 있음 | 생략한 필드는 기존 값 유지. 명시적으로 제공한 수정값은 반영 |
| 연차 조정/일괄 등록이 없는 직원을 참조할 수 있음 | 직원 존재를 쓰기 전 확인. 잘못된 종료일을 시작일로 대체하던 동작도 400으로 거절 |
| 입사 완료 지원자 삭제 허용 | ACCEPTED와 ONBOARDED 모두 연결 기록 삭제 차단 |
| 임금 확정 직전 급여대장이 잠기면 잠금 기록을 덮어쓸 수 있음 | batch 내부의 초안/확정 조건에 급여 잠금 검증 포함. 재개도 상태 재검증. 경쟁 재현 검사 통과 |
| 퇴직 정산 반영 후 임금안 합계가 갱신되지 않거나 동시 수정이 덮어써질 수 있음 | 반영 후 계산 엔진으로 모든 행·합계를 갱신하고 기존 버전이 같은 DRAFT에만 원자적으로 저장 |
| 연간 엑셀이 현재 월 명부/설정을 다른 달에 재사용 | 각 월의 저장된 명부·단수 처리·수당 열 설정으로 출력. 미작성 월은 제외하고 결과 안내 |
| 엑셀 제목 행 고정 옵션이 라이브러리 타입과 불일치 | `stickyRowsCount`로 수정. 실제 XLSX의 2행 고정 확인 |
| 지원자 입력 초기화/임금안 응답의 UI 타입 오류 | 누락된 birth/address와 run 존재 확인 후 타입 추론 보완 |
| 금액 입력 접근성/포커스 검사 오류 | WonInput의 지원되지 않는 ARIA 속성 제거, ref 기반 초기 포커스 |
| 누적 연차 소멸 수치를 ‘올해’로 표시 | 누적 소멸로 표시 문구 정정 |

## 남은 문제와 우선순위

1. **높음 — 브라우저 인센티브의 급여 반영 월 검증 부재.** `app/incentive/incentive-calculator.tsx`의 저장 결과는 savedAt/config/summaries만 담고 정산월이 없다. `app/compensation-calculator.tsx`의 `importIncentive()`는 현재 선택 월에 그대로 적용한다. 같은 결과를 다른 월에 넣을 수 있다. 정산 대상월을 저장·검증하고, 여러 달 매출을 묶는 기준을 확정해야 한다.
2. **높음 — 인센티브 저장 결과가 없을 때 계산 기준 불일치.** `importIncentive()`의 구형 원장 대체 경로가 허들/지급률을 각각 5%로 고정 계산한다. 현재 인센티브 설정, 케이블 원가 및 취소 처리와 일치하지 않을 수 있다. 확정 결과만 가져오도록 하거나 공통 계산기로 통합할 필요가 있다. 이번 검사는 문제를 기록했으며 해당 업무 동작은 변경하지 않았다.
3. **보통 — 기존 UI 정적 검사 미통과.** `hr-workspace.tsx` 32오류/2경고, `compensation-calculator.tsx` 3오류/2경고, `incentive-calculator.tsx` 2오류. 총 37오류/4경고. React effect 내 상태 변경, 렌더 중 Date.now/컴포넌트 생성, 폼 라벨·상호작용 역할·오디오 자막·autoFocus 등이 포함된다. 화면 진입 성공과 접근성/React 규칙 통과는 구분해야 한다.
4. **보통 — 저장소 전체 TypeScript 검사 미통과.** Cloudflare 모듈/D1 전역 타입 선언 누락과 임시·복제 디렉터리를 포함하는 검사 범위 때문에 대량 진단이 발생한다. 수정한 화면의 기존 타입 오류는 해소했으나 저장소 전체 타입 검증 성공으로 주장하지 않는다.
5. **미구현 — 설정 표시 전용 항목.** 회사 정보·일부 기초/알림·백업 설정은 UI 안내대로 아직 실저장 기능이 아니다.
6. **미검증 — 외부 서비스 및 모든 조합.** 실제 AI 전사/이력서 분석/어시스턴트 성공 응답, 실마이크, 운영 계정별 브라우저 접근, 모든 승인정책 조합, 모든 엑셀 입력 변형, 대용량·장시간 부하 및 Cloudflare 운영 D1/R2 환경은 이번 검사로 보증하지 않는다.

## 최종 검증 증거

- `npm test`의 빌드 단계 성공. 변경된 함수 위치·SQL에 맞춰 기존 소스 검사 3개를 수정한 뒤 동일한 전체 Node 테스트 목록 재실행: **383/383 통과, 실패·생략 0**.
- 실제 API 통합 검사: **111개 통과**. 인센티브 계산: **4개 통과**.
- 변경한 핵심 HR API·스키마/설정 헬퍼·WonInput·신규 테스트의 대상 ESLint: 통과. 전체 UI ESLint와 전체 tsc는 위 잔여 항목대로 미통과.
- `git diff --check`: 통과. 기존 파일의 줄바꿈 변환 경고는 별도 존재.
- 브라우저 연간 엑셀: `2026-08`, `2026-09` 2시트. 각각 30행/26행(제목 2행 포함), 두 시트 모두 ySplit=2 확인. 미작성 월 제외 안내 확인.
- 검사 탭 콘솔에는 브라우저 HWP 확장이 html에 추가한 속성의 hydration 불일치 경고가 관찰됐다. 해당 로그를 앱의 업무 API 실패로 집계하지 않았다.
- 재현 코드: `tests/hr-api-integration.test.mjs`, `tests/helpers/hr-api-harness.mjs`, `tests/incentive-calculation.test.mjs`.
- 로컬 검사 로그: `tmp/hr-final-verification.log`(빌드 및 최초 재검사), `tmp/hr-final-tests.log`(최종 383 통과), `tmp/hr-final-lint-core.log`, `tmp/hr-final-ui-lint.json`, `tmp/hr-final-types.log`. 임시 로그에는 기존 소스 경로가 포함되며 배포 산출물이 아니다.
