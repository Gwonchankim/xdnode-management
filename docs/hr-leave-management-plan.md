# HR 월차·연차 관리 기획 (엑셀 대장 → ERP)

작성일 2026-09-21. 2026-09-28 개정(xdnode-management D2-개정·D2-a): 전자결재가 없어져 휴가 신청도 즉시 반영된다(아래 4.4·6-5). 원본: `엑스디노드 월차, 연차관리대장.xlsx` (시트 35개: 휴가 자동화 · 직원별 29개 · 새로들어오실분 · 퇴사자 2개 · 자동화 관리 · 월차 만근).

## 1. 문제 정의

- 연차의 발생·사용·잔여가 구글시트에만 있어 ERP 의 퇴직금 정산(미사용 연차), 급여(연차수당), 대시보드와 끊겨 있다.
- 직원별 시트 29장을 사람이 기호(●○⊙♣♧)로 채우고 `자동화 관리`가 이름으로 다시 찾는 구조라, 이름 변경·시트 추가·행 삽입에 취약하다. 실제로 신효진 잔여 −1.25 처럼 음수 잔여가 시트에 남아 있어도 막지 못한다.
- 월차 발생 조건인 "만근"을 사람이 `월차 만근` 시트에 표시한다. 근태 기록과 연결되지 않아 판단 근거가 남지 않는다.
- ERP 에는 `hr_leave_requests`(신청·승인)만 있고 발생·잔여 개념이 없다. 현재 저장된 신청은 0건이며 화면(`일정·업무`)은 「준비 중」 그룹에 접혀 있다.

## 2. 원본 시트가 담고 있는 규칙 (그대로 옮길 것)

| 항목 | 시트 규칙 | 근거 셀 |
|---|---|---|
| 월차 | 입사 후 1~11개월차, 각 기간을 만근하면 발생일(입사일+n개월)에 1일 | `월차 만근` B~H, `휴가 자동화` D12 |
| 연차 | 입사 1주년부터 매년 기념일에 15일 (연간 부여일수는 `자동화 관리` B3 설정값) | `자동화 관리` I열 |
| 만근 판정 | `월차 만근` F열에 「만근 / 제외 / 공란」. 공란이면 「만근 확인 필요」로 남고 발생하지 않음. 설정 B4 로 「기본 만근 자동 부여」 선택 가능 | `월차 만근` G·H열, `자동화 관리` B4 |
| 사용 단위 | 연차 1 · 반차 0.5 · 반반차 0.25 | 개인 시트 BD열 |
| 차감 제외 | 생일 반차(♣), 공가·대체·경조(♧)는 기록만 하고 잔여에서 빼지 않음 | 개인 시트 BF12 = 연차+반차+반반차만 합산 |
| 이월·소멸 | 미사용분은 소멸 없이 누적 이월 | `휴가 자동화` D14 |
| 과거 사용분 | 시트 하단(예: 임영민 62행 이하)의 전년도 대장을 `과거 별도 사용`(E열)으로 합산 | `자동화 관리` E열 |
| 발생 종료일 | 퇴사자는 D열에 종료일을 넣어 그 날까지만 발생 | `자동화 관리` D·M열 |
| 잔여 | 발생 합계(월차 누계+연차 누계) − 총 사용·예정 | `자동화 관리` K열 |

기록 형식: 개인 시트 AI열 날짜(`2026. 01.15`, `24.05.23` 등 형식이 섞임) + AL열 내용(연차/반차/반반차/생일 반차/공가…). 월별 격자(D~AH열)는 같은 사실을 기호로 다시 그린 것이라 원천 자료로 쓰지 않는다.

## 3. 법정 기준과의 차이 (결정 필요)

근로기준법 제60조 기준과 시트 규칙이 다른 지점이다. ERP 는 규칙을 설정값으로 두어 어느 쪽이든 고를 수 있게 하되, 기본값을 정해야 한다.

| 항목 | 시트 | 법정 | 비고 |
|---|---|---|---|
| 1년 미만 월차 | 만근 시 월 1일, 최대 11일 | 1개월 개근 시 1일 | 같음 |
| 1년 이상 연차 | 매년 15일 고정 | 15일 + 3년차부터 2년마다 1일 가산, 최대 25일 | 시트가 법정보다 적음 (2024-01 입사자는 2027-01 부터 16일) |
| 출근율 80% 미만 | 규칙 없음 | 1개월 개근 시 1일만 | 근태 데이터 없으면 판단 불가 |
| 미사용 연차 | 무기한 이월 | 발생 후 1년 내 미사용 시 소멸(촉진 없으면 수당 지급) | 시트가 법정보다 후함. 회사 방침이면 유지 가능하나 퇴직 정산 시 수당 산정 기준을 명확히 해야 함 |
| 회계연도 통일 | 없음(입사일 기준) | 입사일 기준이 원칙, 회계연도 통일은 선택 | 시트 방식 유지 권장 |

## 4. 목표 설계

### 4.1 데이터 모델 (모두 `app/api/hr/leave/route.ts` 의 `ensureSchema` 로 생성)

- 정책은 상수(6절). 테이블 없음.
- 발생은 저장하지 않고 엔진이 입사일·퇴직일에서 매번 계산한다(자동 부여). 사람이 손댄 것만 `hr_leave_grant_adjustments`(`employee_id`, `grant_key`(MONTHLY-3 / ANNUAL-2 등), `status`(EXCLUDED) 또는 `units`, `note`, `updated_by`)에 남긴다. 시트의 `월차 만근` 「제외」 행 = 조정 1건.
- `hr_leave_requests` — 기존 표 확장. `leave_type` 에 `QUARTER`(반반차), `BIRTHDAY_HALF`(생일 반차), `OFFICIAL`(공가·대체·경조) 추가. `units` 는 지금처럼 정수 ×100(25 = 0.25일). `deducts`(0/1) 열 추가: 연차·반차·반반차만 1. 시트에서 옮긴 과거 기록은 `status = 'APPROVED'`, `source = 'SHEET_IMPORT'` 로 저장한다.
- 잔여는 저장하지 않고 계산한다: `잔여 = Σ grants(GRANTED).units − Σ requests(APPROVED, deducts=1).units/100`. 계산은 `app/hr-leave-accrual.ts` 순수 함수로 두고 `tests/hr-leave-accrual.test.mjs` 로 검증한다(대시보드 모델과 같은 방식).

### 4.2 발생 규칙 엔진 (`app/hr-leave-accrual.ts`)

- 입력: 입사일, 퇴직일(있으면), 기준일, 사용 기록, 조정(제외·일수 변경). 출력: 발생 목록(발생·예정·제외), 잔여, 소멸, 초과 사용, 촉진 대상.
- 월차: n=1..11 에 대해 `grant_date = 입사일 + n개월`, 기간은 `입사일+(n−1)개월 ~ grant_date−1일`. 기준일(퇴직일이 먼저면 퇴직일) 이전이면 GRANTED, 이후면 NOT_DUE. 소멸일은 입사 1주년.
- 연차: 입사 k주년(k≥1)마다 `15 + ⌊(k−1)/2⌋`(최대 25). 소멸일은 발생 1년 뒤. 퇴직일이 있으면 그 이후는 만들지 않는다.
- 사용 배분: 차감 종류(연차·반차·반반차)만 소멸이 이른 발생분부터 FIFO 로 붙인다. 회사 관행상 그 해 발생분을 앞당겨 쓸 수 있어(시트도 발생 합계 − 사용 합계만 본다) 발생일이 사용일보다 늦어도 기준일까지 발생한 것이면 붙이고, 소멸이 지난 발생분에는 붙이지 않는다. 붙일 곳이 없으면 초과 사용으로 잔여가 음수가 된다.
- 촉진: 소멸 183일 전부터 1차, 61일 전부터 2차 대상으로 분류하고 `promotionNoticeText` 가 하이웍스 메일 본문을 만든다.
- 구현: `app/hr-leave-accrual.ts`, 테스트 `tests/hr-leave-accrual.test.mjs`(날짜 표기 4종·기간 표기·말일 입사·가산·제외·FIFO·초과·촉진).

### 4.3 화면

메뉴: 「인사 운영 › 연차관리」를 새로 두고, 접혀 있는 `일정·업무` 의 휴가 신청 부분은 이 화면으로 옮긴다(근태 기록은 그대로 둔다).

1. **잔여 현황 표** — 재직자 전원의 입사일 · 월차 누계 · 연차 누계 · 발생 합계 · 사용 · 잔여 · 만근 확인 필요 건수. 시트의 `자동화 관리` 를 대체한다. 음수 잔여는 빨간 배지.
2. **직원 카드** — 클릭하면 열리는 팝업(공통 팝업 규칙). 상단 요약, 발생 원장(월차 1~11 · 연차 연도별, 상태·확인자), 사용 내역(날짜·종류·차감 여부·상태), 12개월 달력 격자(시트의 ●○⊙♣♧ 기호를 색 배지로 재현). 여기서 「만근 확인 / 제외」와 「휴가 기록 추가」를 바로 한다.
3. **촉진 안내 큐** — 소멸 6개월·2개월 전 대상자를 모아 안내문을 보여 주고 복사·발송 확인을 기록한다(발송은 하이웍스 메일, 추후 자동화).
4. **제외 처리** — 결근 등으로 월차를 주지 않을 달을 직원 카드에서 「제외」로 표시(조정 표).
5. **인사기록카드 탭** — 「연차」 탭에 같은 직원 카드를 넣는다.

### 4.4 다른 모듈과의 연결

- **대시보드 처리 대기함**: 「만근 확인 필요 n건」(주의), 「잔여 음수 n명」(긴급), 「연차 발생 예정 D-7」(참고). 모델 입력에 `leaveSummary` 를 추가한다.
- **퇴직 정산**: `severanceContextFor` 의 `usedLeaveUnits` 를 신청 합계가 아니라 이 모듈의 잔여로 바꾼다. 미사용 연차수당 = 잔여 × 통상 일급(`calculateLeaveAllowance` 그대로).
- **급여**: 급여관리 「연차수당」 칸에 정산 결과를 제안값으로 넣고, 사람이 고친 값이 우선(현재 규칙 유지).
- **즉시 반영**: 휴가 신청(구 양식)도 결재선 없이 편집 권한자가 등록하는 즉시 APPROVED 로 저장한다(`LEAVE_REQUEST_APPROVED` 감사). HR 이 대장에 직접 적는 「기록 추가」도 APPROVED 로 저장하고 `recorded_by` 를 남긴다. 결재 시절에 남은 PENDING 신청은 화면의 승인/반려 버튼으로 처리한다.
- **입사 처리**: 입사 완료 시 발생 예정표가 자동으로 생기므로 별도 작업이 없다. 퇴직 효력 시 `hr_leave_grants` 는 더 만들지 않는다.
- **권한**: 조회 `hr:read`, 기록·확인 `hr:write`, 정책 변경 `hr:approve`. 모든 쓰기는 `writeErpAudit`.

## 5. 이관 (시트 → ERP)

1. 스크립트 `scripts/import-leave-ledger.mjs`(1회 실행). 입력은 xlsx 경로, 출력은 미리보기 표와 `--apply` 시 D1 저장.
2. 사람 매칭: 시트 이름 ↔ `hr_employee_records.name`. 29명 중 26명 일치. 오병석·신원준·최형우 3명은 ERP 도입 전 퇴사자로 인사기록카드에 없어 `--skip-unmatched` 로 건너뛴다(필요하면 인사기록카드에 퇴직자로 등록한 뒤 다시 실행). `새로들어오실분`·`퇴사자`·`퇴사자2` 탭은 `자동화 관리` 목록에 없어 대상이 아니다.
3. 발생: 저장하지 않는다(엔진이 계산). `월차 만근` F열이 「제외」인 행만 조정(EXCLUDED)으로 옮긴다. 현재 시트에는 제외 행이 없다.
4. 사용: 개인 시트 AI/AL 열(현재 대장)과 하단 과거 대장을 모두 읽어 request 로 저장(`source = 'SHEET_IMPORT'`). 날짜 형식 4가지(`2026. 01.15`, `24.05.23`, `2026.02.02`, 시리얼)와 기간 표기(`2026.07.13~16` → 평일마다 1건)를 정규화. 내용 문자열 → 종류 매핑: 연차/반차/반반차(오전·오후 포함)/생일 반차/공가·대체·경조/병가/기타. 매핑 안 되는 문자열·날짜는 미리보기에서 멈춘다.
5. 검증: 시트의 `총 사용·예정`(G열)과 ERP 의 차감 사용 합계가 29명 모두 일치해야 통과(2026-09-21 미리보기에서 29명 전원 일치). 잔여·발생은 회사 결정(가산·소멸·자동 부여) 때문에 시트와 다를 수 있으며 미리보기 표에 소멸·초과 열로 이유를 보여 준다.
6. 이관이 끝나면 시트는 읽기 전용 보관. 이후 기록은 ERP 만 사용한다.

## 6. 결정 사항 (2026-09-21 확정)

1. **연차 가산 적용** — 입사 k주년 부여일수 = 15 + ⌊(k−1)/2⌋, 최대 25일 (근로기준법 제60조 ④).
2. **1년 소멸 + 촉진 절차** — 월차(1년 미만분)는 입사 1주년에, 연차는 발생일로부터 1년에 소멸한다. 소멸 6개월 전(1차)·2개월 전(2차)에 촉진 대상 목록과 안내문을 만든다. 발송은 하이웍스 이메일로 할 예정이며 1단계에서는 안내문 생성까지만 한다.
3. **생일 반차·공가는 차감하지 않음** — 기록만 남긴다.
4. **월차 자동 부여** — 발생일이 지나면 자동으로 GRANTED. 결근 등 예외는 사람이 「제외」로 표시한다(만근 확인 큐 대신 「제외 처리」).
5. **HR 대리 입력만** — 본인 셀프 신청은 두지 않는다. `LEAVE_REQUEST` 결재선은 없어졌고(D2-a), 연차관리 화면의 기록은 즉시 APPROVED 로 저장하고 `recorded_by` 를 남긴다.

정책 테이블(`hr_leave_policies`)은 두지 않고 위 값을 `app/hr-leave-accrual.ts` 의 `DEFAULT_LEAVE_POLICY` 상수로 둔다. 바꿀 일이 생기면 그때 설정 화면을 만든다.

## 9. 연차 원장 팝업 UI 수정 (2026-09-21)

- 일수 입력칸의 기본 너비가 그리드 칸을 넘어 메모칸과 겹치던 문제를 수정했다. 입력칸과 표의 최소 너비·스크롤 범위를 제한하고, 원장 본문 너비에 따라 입력 폼과 요약·표를 줄바꿈한다. 같은 본문을 쓰는 인사기록카드에도 적용된다.
- 범례가 대시보드 차트의 `i` 스타일(10px 원형)을 상속하던 충돌을 제거했다. 사용 내역·범례·달력은 동일한 `LeaveSymbol`과 20px 기호 영역을 사용한다. 연차 ● / 반차 ○ / 반반차 ⊙ 등 기존 대장의 기호를 유지하며, 흰 기호와 어두운 배경 때문에 반대로 보이던 표현을 고쳤다.
- 범례에 8종류를 모두 표시하고, 같은 날짜에 여러 기록이 있으면 모든 기호를 표시한다. 기록 날짜·일수·차감 계산은 변경하지 않는다.
- 브라우저에서 넓은 팝업과 좁은 화면(700px·390px 검증 설정), 인사기록카드 내부의 영역 넘침을 확인했다. 실제 직원의 올해 사용 내역 18건과 달력 기호가 모두 일치했다. 반반차 선택 시 기본 일수 0.25 연동도 확인했다. 실제 기록을 추가하거나 삭제하지 않았다.
- 검증: 빌드 및 전체 테스트 261건 통과, 연차 화면 린트 통과, `git diff --check` 통과.

## 10. 잔여 현황 표 구성 (2026-09-21)

- 소속팀별로 표 본문을 묶고 팀명·인원수를 표시한다. 빈 소속은 ‘소속 미지정’으로 묶는다. 이름·소속 검색 및 퇴직자 포함 조건을 적용한 뒤 그룹을 구성한다.
- 기존 발생 합계 옆에 월차 발생·연차 발생 열을 모두 표시한다. 발생은 입사 이후 누계로, 사용·소멸된 발생분도 포함하되 예정·제외분은 뺀다. 조정 일수도 엔진의 발생 원장과 같은 값을 사용하며 미발생 종류는 0일로 표시한다.
- API가 `grantedByKind`를 제공하고 표에서 월차 + 연차 = 발생 합계가 되도록 연결한다. 일수는 오른쪽 정렬, 잔여 열은 배경과 배지로 강조한다. 직원명·원장 보기 링크는 한 줄을 유지한다.
- 검증: 브라우저에서 재직자 22명·5개 팀과 구매팀 검색 5명 확인. 종류별 합계·소멸·사용·예정·제외·조정 검증 테스트 2건 추가. 빌드 및 전체 테스트 263건, 변경 파일 린트 통과.
