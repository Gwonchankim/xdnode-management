# 채용요청·TO 관리 기획

> 2026-09-28 개정(xdnode-management D2-개정·D2-a): 전자결재가 없어졌다. 모집 시작은 편집 권한자가 누르는 즉시 반영된다(`OPEN`). 결재 시절에 제출돼 남은 `SUBMITTED` 요청은 같은 '모집 시작' 버튼으로 연다.

## 평가

- 승인된 정원 부족과 지원자·채용 제안이 연결되지 않아 중복 충원과 초과 채용을 예방할 수 없다.
- 반대로 인력계획 승인본을 전제로 삼으면 계획이 없는 팀은 채용요청 자체를 남길 수 없어, 실제 채용이 기록 밖에서 진행된다. 등록은 열어 두고 계획 대비 수치는 참고로만 보여준다.
- 지원자 수는 확보 인원이 아니며, 채용 제안 수락으로 입사 예정 인사기록이 생성된 때만 정원에 반영해야 한다.
- 면접 직접 등록은 예외 절차로 유지하되, 정원을 사용하는 채용 제안은 승인된 TO의 잔여 좌석을 검증해야 한다.

## 통제 원칙

1. TO는 등록 버튼으로 팀·포지션·인원수·목표일을 직접 입력해 만든다. 승인 인력계획은 등록 조건이 아니라 참고 지표다.
2. 작성 중·모집 중 TO(레거시 `SUBMITTED` 포함)는 조직 단위 예약 좌석으로 집계해, 인력계획이 있는 조직의 잔여 부족분에 반영한다.
3. TO는 작성, 모집 중, 충원 완료 또는 사유를 남긴 초안 취소·조기 마감 순서로 진행한다. 등록 시 인원 검사를 통과하면 곧바로 모집 중이 되고, 아니면 초안으로 남아 '모집 시작'으로 연다(즉시 반영).
4. 지원자는 하나의 TO에 선택적으로 연결한다. 예외 면접은 허용하지만 TO 없는 채용 제안은 감사기록에 별도로 남는다.
5. TO에 연결된 지원자의 채용 제안은 모집 중인 잔여 좌석과 소속 조직이 일치해야 한다.
6. 채용 제안 수락 시에만 충원 인원으로 계산하고, 목표 인원 도달 시 TO를 자동 완료한다.
7. 잘못 올린 요청안은 사유를 남겨 원장에서 삭제할 수 있다. 지원자가 연결된 요청은 삭제하지 않고 마감·취소로 닫는다.
8. 모든 생성·모집 시작·마감·삭제는 감사기록에 남긴다. 삭제 기록은 삭제 직전 요청안 전체를 함께 보관한다.

## 화면 산식

- 계획 부족 = 승인 정원 - (현재 재직 + 입사 예정 - 계획 퇴사)
- 예약 TO = 같은 조직의 작성/모집 중 TO의 요청 인원 - 이미 수락된 인원
- 추가 요청 가능 = 계획 부족 - 예약 TO (인력계획이 있는 조직만 산출하며, 등록을 제한하지 않는다)
- TO 잔여 = 요청 인원 - 수락 완료 인원
