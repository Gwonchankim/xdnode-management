# ERP 통합 감사·변경이력 센터 기획·평가

## 1. 기존 상태 평가

- HR·재무회계·영업·설정의 주요 쓰기 API는 `erp_audit_logs`에 처리자, 대상, 변경 전후 값, 사유와 시각을 기록한다.
- 데이터 통제 센터는 감사기록 CSV를 만들 수 있지만, 운영자가 화면에서 특정 직원·원장·작업을 즉시 찾거나 변경 전후 값을 비교할 수 없다.
- 통합 업무함은 현재 할 일을 보여주지만 이미 처리된 변경의 책임과 근거를 조사하는 화면은 아니다.

따라서 다음 우선 기능은 신규 업무 원장이 아니라, 이미 구축된 업무 원장의 신뢰성을 운영자가 직접 검증하는 공통 감사 화면이다.

## 2. 최초 기획

- 전 모듈의 최근 감사기록을 한 화면에 표시한다.
- 기간, 모듈, 작업, 검색어로 조회한다.
- 변경 전후 JSON과 처리 사유를 펼쳐 본다.
- CSV 내보내기와 연결한다.

## 3. 위험 평가와 개선

1. 감사 원장을 수정하는 기능은 제공하지 않는다. 조회는 관리자 전용 `audit:read` 권한으로 제한한다(R3, 감사 탭은 adminOnly).
2. API 토큰, 비밀번호, 인증 헤더 같은 보안 키는 서버 응답 전 가린다.
3. 전체 원장을 브라우저로 보내지 않고 30건씩 `(created_at, id)` 커서로 페이지를 넘긴다.
4. 검색은 감사 JSON 원문까지 확장하지 않는다. 작업, 대상 유형·ID, 처리자, 사유만 검색해 개인정보의 불필요한 노출과 전수검색을 줄인다.
5. 화면 조회 자체가 새로운 감사기록을 계속 만드는 순환 로그가 되지 않게 읽기 요청은 원장을 변경하지 않는다.
6. CSV 증적 생성은 기존 데이터 통제 기능을 유지하고, 화면은 조사·원인 확인에 집중한다.

## 4. 구축 범위

- 데이터 통제 센터에 `감사·변경이력` 탭 추가
- 관리자 전용 `/api/audit-log` 조회 API
- 기간·업무 영역·작업·통합 검색과 안정적인 커서 페이지네이션
- 처리자 이름, 이메일, 작업, 대상, 사유, 변경 필드 요약
- 변경 전후 원문 펼치기와 보안 키 서버 가림
- 전역 최신 조회를 위한 `created_at, id` 인덱스

## 5. 검증 기준

- 비관리자 요청이 거부된다.
- 사용자 입력은 바인딩하며 SQL 문자열로 합성하지 않는다.
- 동일 시각 기록도 ID 보조 정렬로 누락·중복 없이 다음 페이지를 조회한다.
- 보안 키 값이 응답에 포함되지 않는다.
- 감사 원장에 수정·삭제 경로가 없다. 즉, UPDATE·DELETE를 제공하지 않는다.
- 기존 데이터 통제·연동·업무함 기능과 전체 빌드가 회귀 통과한다.

## 6. 다음 우선순위

1. 전사 기준정보 변경 영향도: 계정·조직·거래처 변경이 연결 원장에 미치는 영향 사전 점검
2. 업무 예외 SLA: 경보·결재·대사·마감의 기한 초과와 재발 빈도 분석
3. 경영 운영 대시보드: 재무·영업·HR 핵심 지표를 동일 기준일과 출처로 묶어 조회
4. 정기 접근권한 재검토: 재직상태·역할·최종 사용 이력을 근거로 분기별 권한 확인
