# 인력계획·정원 운영 기획·평가

> 2026-09-28 개정(xdnode-management D2-개정·D2-a): 전자결재가 없어졌다. 아래의 승인·확정 단계는 편집 권한자가 누르는 즉시 반영된다. 결재 시절에 제출돼 남은 `SUBMITTED` 행은 같은 버튼으로 처리한다.

## 1. 현재 평가

- 화면의 현재 인원만 실제 인사자료이고 승인 정원·충원 필요는 미입력 상태다.
- 정원 수치를 누가 언제 바꾸었는지, 경영진이 승인했는지, 과거 계획과 무엇이 달라졌는지 남지 않는다.
- 재직자와 입사 예정자를 같은 인원으로 합산하면 현재 가동 인원과 미래 예상 인원을 구분할 수 없다.
- 지원자 수는 채용 경쟁도이지 확보 인원이 아니므로 정원 충족 인원으로 계산하면 안 된다.

## 2. 개선된 원칙

1. 계획은 반기별 버전 원장으로 저장하고 `DRAFT → APPROVED`로 확정한다. 확정은 결재 없이 편집 권한자의 '승인·확정'으로 즉시 반영한다(레거시 `SUBMITTED`도 같은 버튼으로 확정).
2. 같은 반기에 새 버전이 승인되면 기존 승인본은 `SUPERSEDED`로 보존한다.
3. 조직별 승인 정원과 계획 퇴사만 계획 원장에 저장한다. 현재 재직·입사 예정은 인사기록 원장에서 매번 다시 계산한다.
4. 예상 가동 인원은 `현재 재직 + 입사 예정 - 계획 퇴사`로 계산한다.
5. 충원 필요는 `max(승인 정원 - 예상 가동 인원, 0)`, 초과는 반대 방향으로 별도 표시한다.
6. 정원이 현재 예상 인원보다 작으면 감원·전환 근거가 되는 메모를 필수로 남긴다.
7. 지원자, 면접자 수는 정원 충족으로 인정하지 않는다. 승인된 채용 제안을 수락해 `입사 예정` 인사기록이 생성된 시점부터만 반영한다.

## 3. 화면과 동작

- 요약: 현재 재직, 입사 예정, 승인 정원, 충원 필요
- 조직 원장: 현재 재직, 입사 예정, 계획 퇴사, 예상 가동, 승인 정원, 충원 필요·초과, 근거
- 계획 작성: 반기·제목·가정 등록, 조직별 정원과 계획 퇴사 저장
- 통제: 승인·확정은 즉시 반영하고 확정본은 편집 잠금, 수정은 개정본 생성으로 한다
- 출처: 실제 인원은 인사기록, 승인 정원은 인력계획 버전으로 명확히 표시

## 4. 검증 기준

- 같은 반기·버전 및 같은 계획·조직은 중복 저장되지 않아야 한다.
- 재직자·입사 예정자·퇴직자는 서로 다른 산식으로 집계되어야 한다.
- 정적 회사 인원과 저장된 인사기록 수정분이 중복 집계되지 않아야 한다.
- 확정본은 수정할 수 없고, 확정은 현재 상태 조건(`DRAFT`·`SUBMITTED`)을 건 한 batch로 반영되어 동시 확정 시 한 번만 성공해야 한다.
- 과거 승인본은 삭제하지 않고 대체 상태로 남아야 한다.
