# 매입채무·지급예정 관리 기획 및 평가

## 기존 기능 평가

- 발주, 승인, 입고·검수, 매입 인보이스, 지급요청, 실제 지급은 원장으로 연결되어 있다.
- 지급 전 채무를 만기·우선순위·담당자·내부 지급예정일 기준으로 운영하는 화면이 없었다.
- 인보이스 번호 중복 기준이 회사 전체 단일값이어서 서로 다른 공급사의 같은 번호까지 차단했다.
- 자금예측은 공급사 원천 지급기한을 사용하며 내부 지급계획을 반영하지 못했다.

## 개선 원칙

1. 인보이스 총액과 공급사 지급기한은 원천값으로 유지한다.
2. 내부 지급예정일, 우선순위, 담당자, 보류 사유와 메모는 별도 지급계획으로 저장한다.
3. 인보이스 중복은 공급사와 인보이스 번호 조합으로 차단한다.
4. 지급계획은 대사 완료 후 실제 지급 전까지만 수정한다.
5. 지급 보류에는 반드시 사유를 남긴다.
6. 내부 지급예정일은 13주 자금예측의 일자를 보완하되 채무 금액이나 원천 지급기한을 바꾸지 않는다.
7. 지급 완료는 승인된 지급요청이 실제 지급원장에 기록될 때만 발생한다.

## 화면과 알림

- KPI: 지급 전 채무, 기한 경과, 일정 미설정, 지급 예정, 보류
- 에이징: 기한 내, 1~30일, 31~60일, 60일 초과, 기한 없음
- 지급 큐: 공급사, 인보이스 번호, 원천 지급기한, 내부 지급예정일, 우선순위, 금액
- 알림: 기한 경과, 일정 미설정, 날짜 누락, 지급일 도래, 지급 보류

## 검증 기준

- 같은 공급사의 같은 인보이스 번호는 중복 저장할 수 없다.
- 서로 다른 공급사는 같은 인보이스 번호를 사용할 수 있다.
- 지급 예정 상태에는 내부 지급예정일이 필수다.
- 지급 보류 상태에는 보류 사유가 필수다.
- 내부 지급계획은 미지급 채무에만 저장할 수 있다.
- 지급계획이 있는 채무는 자금예측에서 계획일을 사용하고 중복 집계하지 않는다.

## 후속 설계

현재 지급원장은 승인된 요청을 전액 지급하는 구조다. 부분지급·분할지급은 지급요청과 결재금액, 잔액, 역지급까지 함께 바꾸어야 하므로 별도 통제 설계 후 구현한다.
