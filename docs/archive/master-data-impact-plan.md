# 전사 기준정보 변경 영향도 기획·평가 기록

## 목표

계정과목·재무 거래처·은행계좌·세금코드·영업 거래처·HR 조직을 수정, 비활성화 또는 병합하기 전에 실제 연결 원장을 계산해 운영 장애와 고아 데이터를 예방한다.

## 1차 기획과 평가

최초안은 변경 화면에 종속 건수만 표시하는 방식이었다. 그러나 화면을 확인한 뒤 결재가 끝나기 전 새 전표·미수금·계약이 생기면 최초 결과만으로는 안전을 보장할 수 없었다. 또한 브라우저 상태만 이용하면 새로고침·다른 기기·직접 API 호출에서 통제가 우회된다.

## 개선안

1. 변경 직전 D1 운영 원장을 조회해 차단·주의·참고 항목과 금액을 계산한다.
2. 계산 결과, 대상 버전, 체크섬, 요청자, 만료시각을 `erp_master_impact_assessments`에 15분 동안 동결한다.
3. 쓰기 API가 대상·작업·버전·체크섬·미사용 여부를 서버에서 다시 검증한다.
4. 성공한 변경 또는 결재 요청과 같은 처리 흐름에서 확인 기록을 일회성으로 사용 처리한다.
5. 재무 마스터는 최종 결재 직전 원장을 다시 계산하고 새 차단 항목이 있으면 승인을 중단한다.

## 위험 규칙

- 계정과목: 미전기 분개, 활성 은행 GL 연결, 미완료 지출, 운영 중 고정자산은 비활성화 차단.
- 재무 거래처: 미전기 거래처 분개, 진행 중 영업·구매 원장은 비활성화 차단.
- 은행계좌: 미분류 거래가 남으면 비활성화 차단.
- 세금코드: 미전기 세금 분개가 남으면 비활성화 차단.
- 영업 거래처: 진행 중 영업기회, 미수 청구, 유효 계약, 미종결 고객 이슈는 비활성화를 차단한다. 병합은 영향 건수를 경고하고 영업기회·계약·청구·고객 이슈를 대상 거래처로 함께 승계한다.
- HR 조직: 조직 ID를 유지하므로 이름 수정은 허용하되 재직자·인력계획·채용요청·성과평가·교육 영향을 명시한다.

## 통제 원칙

- localStorage나 화면 상태를 승인 근거로 사용하지 않는다.
- 모든 식별자와 값은 바인딩하며, 대상·작업 유형은 서버 허용목록으로 제한한다.
- 과거 전표·계약·평가 스냅샷은 자동 수정하거나 삭제하지 않는다.
- 차단 항목은 사용자가 원장을 먼저 정리해야 하며 시스템이 자동 병합·자동 계정 치환하지 않는다.
- 확인 기록은 만료·재사용·원장 변경 시 거부한다.

## 완료 기준

- 세 업무 영역의 변경 화면에서 동일한 영향도 대화상자를 사용한다.
- 영향도 확인 없는 직접 쓰기 요청이 서버에서 거부된다.
- 재무 최종 승인 시점에 새 차단 항목을 다시 확인한다.
- 마이그레이션, 권한 검사, 정적 분석, 전체 회귀 테스트, 운영 빌드가 통과한다.
