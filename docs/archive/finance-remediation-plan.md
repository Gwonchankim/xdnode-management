# 재무회계 개편 계획

## 전제

이카운트/Clobe가 정본 장부이고 분개장은 그쪽에서 import된다. XD NODE는 분개를 만드는 곳이 아니라 **정본 원장의 검증·분석 레이어**다. 운영은 1인 로컬(`LOCAL_ERP_USER_EMAIL` 기반 `SUPER_ADMIN`, `app/chatgpt-auth.ts`).

이 두 전제가 바뀌면(예: 배포 재개, 인원 증가, XD NODE 자체를 정본 장부로 전환) 아래 범위 결정부터 다시 검토해야 한다.

## 범위

**범위 안**
- 대사 엔진 — 원천 ↔ 장부 ↔ 신고 3-way, 보조부 ↔ GL tie-out
- 결손 탐지 — 부가세 미상계, 매출원가 누락, 충당금 미설정을 찾아 경보
- 세무 값 정밀화 — 세액 필드, 과세유형, 원천징수 항목 분해
- 회계 표시 정확성 — 계정분류, 손익 라인, 유동·비유동 구분
- 데이터 신뢰성 — 기준일 단일화, 스냅샷 자체 검증, 출처 추적
- 화면 재편 — 출처 배지, 대사 보드, 경보 피로 해소

**범위 밖**
- 보조부 자동분개(매출원가·매입채무·대손·처분손익 전표 생성) — 정본이 아니므로 만들지 않는다
- 결산분개(집합손익 → 이익잉여금 대체) — 이카운트가 한다
- 부가세 정산분개 — 탐지만 하고 분개는 만들지 않는다
- 간이세액표 자동 계산 — 부양가족 정보가 없다. 외부 산출값을 받아 대사한다
- 이연법인세 — 일시적차이 관리 데이터가 전무하다
- 직무분리(SoD) 강제 — 1인 운영. 대신 단독 승인 사실을 기록으로 남긴다

## 순서와 근거

| 단계 | 내용 | 왜 이 순서인가 |
|---|---|---|
| 0 | 기준 확정 | 기준일이 어긋난 채 대사하면 나온 차이가 진짜인지 기준 차이인지 구분 불가 |
| 1 | 정본 분리 | 대사의 한쪽 변이 오염돼 있으면 tie-out을 만들어도 항상 틀린다 |
| 2 | 대사 축 | 검증 레이어의 본체. 규모가 가장 크다 |
| 3 | 세무 정밀화 | 세무 3-way는 일반 3-way 틀 위에 얹는 특수 케이스 |
| 4 | 화면 재편 | 보여줄 것이 확정된 뒤에 짜야 두 번 안 한다 |

순서와 무관하게 즉시 처리: 자금일보 통화 필터, 기간검증 연도 하드코딩 제거, 감가상각 전표일 — **2026-08-26 완료 (본 세션)**.

## 단계 0 — 기준 확정 (M · 3~5일 + 실무 확인)

지금은 같은 개념이 세 개의 기준일을 갖는다 — 스냅샷 asOf, 세금계산서 인사이트 as-of, 실제 최종 전표일. 이 격차가 매출 예측에서 34.6억 차이를 만든다.

- **세무회계 값**: 판관비 모순 규명(실무 확인) · 부가세 계정 실사(세무대리인) · 급여 원천징수 실태(명세서 원본) · 2025 시산표 부호 이상 정리 · 매입 구성 분해(상품매입/수입/판관비성)
- **데이터 가공·처리**: as-of 상수 통합, 스냅샷에 `dataThrough` 신설, 생성 스크립트에 자체 검증(금액·건수 양방향 대사, 부호 검사, 날짜 범위) 추가, `differenceKrw` 부호 정정, 세금계산서 건수 −78건 원인 규명, 배열별 커버리지 메타
- **기능**: 파생 계산 기준일 통일, 예측 시나리오 축퇴 해소, 스냅샷 품질 게이트
- **UI·UX**: 출처 배지 체계(정본원장/세금계산서/은행/스냅샷/추정), 기준일 바 고정, 수치 클릭 시 출처 팝오버, CSV 헤더에 기준일·출처·품질상태

완료 기준: 화면의 임의 숫자를 짚어 "언제까지의, 어디서 온 값인가"를 즉답할 수 있다.

## 단계 1 — 정본 분리 (L · 5~8일)

`finance_journal_entries`(ERP 지급전표)가 마감잠금·계정마스터·결재를 우회하며 정본 원장에 합산되는 문제를 원장 집계에서 제외하는 방식으로 해결한다.

- **세무회계 값**: 계정분류를 계정 마스터 기준으로 전환(코드 첫자리 휴리스틱은 폴백), 4/5자리 코드 정규화, 손익계산서 라인 세분화(매출/매출원가/판관비/영업외수익/영업외비용/법인세), 재무상태표 유동·비유동 구분, 이월이익잉여금 행 신설
- **데이터 가공·처리**: `finance_journal_entries`를 원장 집계에서 제외, 계정 마스터에 `statement_line`/`liquidity`/`contra_of`/`code_aliases` 추가, 분류 로직 이중화 해소
- **기능**: 회계등식 검증 재설계(YTD 고정 + 분류 검증 편입), DRAFT/OFFICIAL 판정 강화, 지급전표를 "지급 실행 기록"으로 재정의, 마감 SUBMITTED 구간 원장 잠금, 감사 가드레일 테스트를 재무 23개 라우트로 확장
- **UI·UX**: 원장 화면에 "이카운트 import분만" 고정 문구, 손익계산서 표준 양식 재렌더, 지급 실행 기록 탭 분리, "당기순이익" 라벨 정정

완료 기준: 조회 시작일과 무관하게 회계등식 성립, 영업이익 산출, OTHER 버킷 0.

## 단계 2 — 대사 축 (XL · 8~12일, 최대 규모)

- **세무회계 값**: 보조부 ↔ GL tie-out 5종(재고자산·매출채권·매입채무·유형자산 장부가·차입금), 은행계정조정표, 대손충당금 권장액 산출, 매출원가 추정 대사, 유형자산 처분손익 계산, 부가세 미상계 탐지
- **데이터 가공·처리**: `finance_reconciliation_statements` 신설, 보조부별 as-of 잔액 표준화, 미수잔액 산식 단일화, 재고 이동평균 교정, `blockedPeriods()` 일원화
- **기능**: 월마감 통제를 체크리스트에서 잔액 일치 검증으로 전환, 대사 차이 사유 등록(구조적/미확인 분리), 회계기간 개설을 명시적 행위로 분리, 낙관적 잠금 표준화
- **UI·UX**: 대사 현황 보드, 차이 드릴다운, 마감 화면 재편(PASS/FAIL이 아닌 차이 금액 중심)

완료 기준: 월마감 시 tie-out 5종 + 은행조정 + 부가세 탐지가 금액으로 나오고, 미해소 차이가 있으면 마감 차단.

## 단계 3 — 세무 정밀화 (L · 5~8일)

자동 계산 도입이 아니라 수기 입력값을 검증할 수 있는 구조를 만든다.

- **세무회계 값**: 공급가액·세액 분리, 세금코드 과세유형(과세/영세율/면세/불공제/대상외), 불공제 매입세액 원가가산 누락 탐지, 원천징수 항목 분해(사용자부담분 별도), 비과세 한도 상수 + 시행일자 이력, 퇴직소득 분리
- **데이터 가공·처리**: `finance_tax_periods`에 장부 계상액 추가(3-way 완성), 신고 주기 필드, 구조적 차이 입력란, 수정세금계산서 사유코드
- **기능**: 세무 검토 완료 조건을 금액 임계치 기반으로 강화, 활성 세금코드 검증 강화, 부가세 신고 요약표(홈택스 대조용), 매입 세액 대조 경고
- **UI·UX**: 세무 화면 3-way 대사 표, 차이 사유 구조적/미확인 분리, 급여 명세 항목별 공제 표, 퇴직정산 라벨 정정

완료 기준: 부가세 신고 시즌에 홈택스 값과 대조해 차이 사유를 전부 설명 가능. 급여대장에서 원천징수영수증으로 이어지는 항목이 빠짐없이 저장.

## 단계 4 — 화면 재편 (L · 5~8일)

- **데이터 가공·처리**: 정적 스냅샷 파생 화면과 실시간 원장 화면의 데이터 경로 분리 명시, 리스크 모델 재보정, 중앙값 기준선 레벨시프트 보정, 은행거래 분류율 개선
- **기능**: 자금예측 회수확률 연령구간별 차등, 자금일보 7일 예정액 이중계상 해소, 최소운영자금 저장 버그 수정, 경보 임계값 재설정
- **UI·UX**: 24개 화면을 목적별 3군(대사·검증/경영판단/실행기록)으로 재그룹, 스냅샷 배지 상시 노출, 첫 화면을 "오늘 조치할 것" 중심으로, CSV를 승인된 원장 기준으로 전환

완료 기준: 첫 화면에 뜬 항목이 전부 실제 조치 대상. 스냅샷 기반과 원장 기반 숫자가 시각적으로 구분.

## 착수 전 선행 확인 (코드로 풀 수 없음)

1. **2025년 판관비가 실제로 얼마인가** (대표 확인) — 재무 히스토리 함의 30,648,039원 vs 급여대장 인건비 463,676,242원. 매출총이익률·손익 추세·예산 실적 전부의 전제.
2. **부가세 계정 잔액이 정상인가** (세무대리인) — 대급금 4,393,035,450원·예수금 5,013,279,478원 2년 미상계, 미지급세금 계정 없음.
3. **원천징수를 실제로 했는가** (급여 원본) — 287행 중 284행 공제 0원. 단계 3 설계가 이 답에 달려 있음.

## 1인 로컬 운영에 따른 조정

진단에서 HIGH로 잡았으나 로컬 단독 운영 확인 후 등급을 내린 항목. 없애지 않고 기록으로 남기는 형태로 전환.

- 자기결재 차단 강제하지 않음 — 대신 감사기록에 "단독 승인" 플래그
- 재무 결재선 2단계 → 1단계 축소 검토(현재 `FINANCE_ADMIN → SUPER_ADMIN`이 동일인으로 수렴)
- `finance:admin` 권한은 역할 맵에 명시만
- 감사증적은 그대로 유지, 가드레일 테스트는 단계 1에서 확장
