# 프로젝트·원가센터 손익 기획안

## 평가

- ERP 영업 청구서는 영업기회 ID를 보유하므로 프로젝트와 정확히 1:1 연결할 수 있다.
- 구매 인보이스·일반 지출·급여월에는 프로젝트 차원이 없으며 명칭·거래처·부서 유사도로 자동 배부하면 왜곡된다.
- Clobe 세금계산서 스냅샷은 문서 ID가 없는 일·거래처 집계이므로 프로젝트 손익 원천으로 자동 배부할 수 없다.
- 기존 부서 예산은 전사 원천만 자동 대사하며 프로젝트 단위 예산과 실제 연결은 없다.

## 기획 원칙

1. 영업기회와 명시적으로 연결한 프로젝트의 승인 청구서만 매출로 자동 귀속한다.
2. 구매·지출·잠긴 급여는 원천 금액 범위 안에서 수동 금액 배부하며 배부 사유를 남긴다.
3. 공통비는 임의 비율 배부하지 않고 `OVERHEAD` 원가센터에 분류한다.
4. 한 원천의 전체 프로젝트·원가센터 배부 합계는 원천 금액을 초과할 수 없다.
5. 월마감은 프로젝트 대상 원천의 미분류 잔액과 승인 예산 초과를 자동 확인한다.
6. 마감 잠금 월의 예산·배부는 변경할 수 없으며 배부 삭제는 승인 권한과 감사로그를 요구한다.
7. 프로젝트 손익은 ERP 승인 청구서·대사된 구매 인보이스·지급 완료 지출·잠긴 급여만 사용한다.

## 구축 범위

- 프로젝트·부서·간접비 원가센터 마스터
- 영업기회 1:1 프로젝트 연결
- 월별 매출·원가 예산
- ERP 원천 후보, 직접 금액 배부, 잔액·중복·초과 검증
- 프로젝트별 매출·원가·이익·이익률·예산차이
- 미분류 원천 및 예산 초과 운영 알림·월마감 통제

## 제외 범위

- Clobe 집계자료의 프로젝트 자동 배부
- 거래처명·품목명·부서명 기반 추정 배부
- 근태·타임시트가 없는 급여의 자동 인건비 배부
- 세금·자금이동·매입부가세를 프로젝트 원가로 중복 반영
