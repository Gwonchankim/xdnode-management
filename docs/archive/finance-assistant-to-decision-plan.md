# 재무 어시스턴트 답변 → 경영 의사결정 연결 기획·평가

## 1. 현재 상태 평가

- 재무 어시스턴트 답변은 질문·답변·원천 전체·답변/근거 해시와 작성자를 수정 불가능한 이력으로 보존한다.
- 월간 경영보고는 버전, 전자결재, 구조화 의사결정 안건, 결정 결과와 후속조치를 이미 별도 원장으로 관리한다.
- 그러나 답변을 참고해 안건을 수기로 다시 입력하면 어떤 답변과 근거를 사용했는지 추적할 수 없고, 복사 과정에서 내용이 달라질 수 있다.

## 2. 최초 기획안 평가와 보정

최초 아이디어는 답변에서 업무를 바로 만드는 것이었다. 다음 위험 때문에 그대로 채택하지 않는다.

- AI 또는 규칙 기반 답변은 조언이며 승인된 회계 전표나 경영 결정이 아니다.
- 품질경고가 있는 답변에서 업무가 자동 생성되면 검토 절차를 우회할 수 있다.
- 같은 답변을 여러 번 실행업무로 전환하면 중복 조치가 발생한다.

따라서 `답변 → 안건 초안 → 보고서 제출 → 전자결재 → 안건 확정 → 후속조치` 순서로 제한한다.

## 3. 개선된 구축 정책

1. 저장이 완료된 답변만 경영 안건으로 제안할 수 있다.
2. 안건에는 답변 ID, 답변 해시, 근거 해시, 근거 기준일과 검증 상태를 동결해 연결한다.
3. 연결 시 제목·요청내용·유형·책임자·기한·재무영향을 사용자가 확인하고 편집한다.
4. `REVIEW_REQUIRED` 답변은 근거 제한 확인 동의 없이는 안건으로 저장하지 않는다.
5. 안건은 항상 `DRAFT`로 생성하며 보고서 제출·전자결재를 자동 실행하지 않는다.
6. 보고서가 승인된 뒤 별도의 승인권자가 안건을 승인·보류·반려한다.
7. 승인 또는 보류된 안건에서만 기존 정책에 따라 후속조치를 한 번 생성한다.
8. 동일 보고서에는 동일 답변을 한 번만 연결하고, SQLite 고유 인덱스로 중복을 차단한다.
9. 일반 수기 안건에는 빈 원천 필드를 유지해 기존 데이터와 기능을 보존한다.
10. 연결된 안건에서 원문 근거를 열면 최근 목록 범위와 관계없이 해당 답변 이력을 ID로 다시 조회한다.

## 4. 검증 기준

- 답변 이력이 없는 임의 ID는 연결할 수 없어야 한다.
- 제출·승인된 보고서에는 새 답변을 연결할 수 없어야 한다.
- 검토 필요 답변은 확인 동의 없이는 연결할 수 없어야 한다.
- 동일 보고서와 답변 조합은 두 번 저장되지 않아야 한다.
- 연결된 안건에 답변·근거 해시와 기준일이 노출되어야 한다.
- 연결 직후에는 업무나 전표가 생성되지 않아야 한다.
- 기존 보고서 제출·승인·안건 확정·후속조치 생성 규칙이 그대로 적용되어야 한다.
