# 고객지원·반품 통제 기획안

## 평가

- 현재 영업 흐름은 계약·납품·청구까지 이어지지만 납품 이후 문의, 하자, 반품, 교환, 환불을 추적할 원장이 없다.
- 응답·해결 기한이 구조화되지 않아 서비스 수준 위반과 장기 미결 건을 알림으로 잡을 수 없다.
- 반품 수량, 재입고, 환불 지급이 원 납품과 연결되지 않아 중복 반품과 임의 환불 위험이 있다.

## 개선된 통제 설계

1. 확정 납품을 기준으로 고객 서비스 케이스를 만들고 거래처·영업기회·계약을 자동 연결한다.
2. 우선순위별 응답·해결시간은 승인된 SLA 정책에서 계산한다. 활성 정책이 없으면 담당자가 두 기한을 명시해야 하며 임의 기본값을 만들지 않는다.
3. 모든 메모, 최초응답, 처리안, 승인, 종결은 추가 전용 이벤트로 남긴다.
4. 반품·교환·환불 수량은 원 납품행의 수량을 초과할 수 없고, 다른 미반려 케이스에 이미 배정된 수량도 차감한다. 조회와 저장을 나누지 않고 원장의 단일 조건부 쓰기로 처리해 동시 요청도 초과되지 않게 한다.
5. 모든 처리안은 공통 전자결재를 통과해야 한다. 승인 전에는 재고·환불 후속 원장을 만들지 않는다.
6. 환불 승인 시 재무 지급요청 초안을 자동 생성하되 증빙 등록·재무 결재·지급·전표 절차는 기존 재무 통제를 그대로 거친다. 같은 납품에 연결된 결재 중·승인·완료 환불의 누적액도 원 납품금액을 넘을 수 없다.
7. 재입고는 재무 권한자가 상품·창고·실제 단가를 명시한 경우에만 `SALES_RETURN` 재고이동으로 반영한다. 상품 매핑이나 원가는 추정하지 않는다.
8. 교환은 대체 납품 업무가 완료되어야 하고, 환불은 실제 지급 완료, 재입고는 모든 대상행 반영 후에만 케이스를 종결한다. 격리·폐기·공급사 반송은 승인 시 담당 업무를 생성하고 그 업무가 완료되어야 종결한다.
9. 최초응답·해결기한 경과, 승인 후 미처리 반품·환불·교환을 통합 알림에 노출한다.

## 상태와 경계

- SLA 정책: `DRAFT → SUBMITTED → ACTIVE/REJECTED`, 같은 우선순위의 기존 활성 버전은 승인 시 퇴역한다.
- 케이스: `OPEN → IN_PROGRESS → RESOLUTION_SUBMITTED → RESOLUTION_APPROVED/RESOLVED → CLOSED`
- 승인 반려 시 케이스는 `IN_PROGRESS`로 돌아가며 기존 이벤트와 처리안은 보존한다.
- 확정 처리 근거 문서는 삭제할 수 없다.

## 검증 기준

- 활성 SLA가 없을 때 명시 기한 없이 케이스를 생성할 수 없다.
- 원 납품행을 초과하거나 중복 배정하는 반품행은 저장되지 않는다.
- 최초응답과 처리 근거 문서가 없으면 처리안 결재를 제출할 수 없다.
- 승인 전 재고입고·환불 초안이 만들어지지 않는다.
- 재고·지급·교환·격리·폐기·공급사 반송 후속 업무가 남아 있으면 종결할 수 없다.
- 동시 요청을 포함한 여러 케이스의 누적 반품수량과 누적 환불액이 원 납품 한도를 넘으면 원장의 원자적 조건부 저장이 변경 없이 종료된다.
