# 영업 계약·이행 관리 기획안

## 평가

- 현재 승인된 수주는 바로 납품·청구의 근거가 되지만 실제 서명 계약서와 구조화된 계약조건이 없다.
- 계약기간, 검수기준, 대금조건, 납품조건, 담당자, 갱신통지기한과 이행 의무가 문서 상태에 축약되어 있다.
- 조건을 바꿀 때 원문·변경사유·승인결과를 함께 보존하는 변경합의 원장이 없다.

## 개선된 통제 설계

1. 승인·완료된 수주 하나당 계약 원장 하나를 만든다. 수주 금액은 계약 생성 시 스냅샷으로 고정한다.
2. 계약기간·대금조건·검수기준·납품조건·담당자·자동갱신·갱신통지일을 구조화한다.
3. 계약 활성화 전 서명 계약서와 최소 한 개의 이행 의무를 요구한다.
4. 계약 활성화는 공통 전자결재를 거치며 승인 후에는 초안 필드를 직접 수정하지 않는다.
5. 활성 계약의 조건 변경·기간 변경·담당자 변경·종료는 변경요청의 전후 스냅샷과 사유를 남기고 별도 결재한다.
6. 이행 의무는 담당자·기한·증빙 필요 여부를 기록하고 완료 근거를 남긴다.
7. 도입 시점 이후 생성된 수주는 활성 계약 없이 납품 또는 직접 청구할 수 없다. 도입 이전 수주는 기존 운영을 보존한다.
8. 계약 만료·갱신통지·기한 경과 의무는 통합 알림 업무로 생성한다.

## 상태와 경계

- 계약: `DRAFT → SUBMITTED → ACTIVE → TERMINATED/EXPIRED`
- 의무: `OPEN → IN_PROGRESS → COMPLETED`
- 변경요청: `SUBMITTED → APPROVED/REJECTED`
- 활성 계약에 대한 직접 덮어쓰기는 금지하고, 승인된 변경요청만 계약 버전을 1 증가시킨다.
- 서명 계약서와 승인·변경에 사용된 문서는 감사 이력 보호를 위해 삭제할 수 없다.

## 검증 기준

- 수주 문서와 계약 번호는 각각 중복되지 않는다.
- 서명본 또는 의무가 없으면 계약 결재를 제출할 수 없다.
- 도입 이후 수주는 활성 계약 없이 납품·직접 청구를 만들 수 없다.
- 계약 변경 승인 결과가 변경요청과 계약 원장에 한 트랜잭션 흐름으로 반영된다.
- 만료·갱신·기한 경과 의무가 운영 알림에 나타난다.
