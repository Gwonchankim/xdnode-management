# 재무 파일 매핑·검증 통제 기획

## 평가

통합 재무 마스터와 파일 원본 보관·전자결재는 존재하지만, 이카운트·Clobe 파일의 열 이름과 계정·거래처·부서를 표준 원장 값으로 연결하는 승인된 규칙이 없었다. 따라서 승인된 파일도 재무 원장에 직접 반영해서는 안 된다.

## 개선된 기획

1. 원천 파일과 행별 체크섬은 변경하지 않는다.
2. 원천 열을 표준 필드로 연결하는 매핑 세트를 원천·자료유형·버전별로 관리한다.
3. 매핑 세트는 초안 저장 후 재무 검토와 대표 승인을 거쳐야 활성화된다.
4. 계정·거래처·부서·은행계좌는 정확 일치 또는 사람이 등록한 규칙만 사용한다. 명칭 유사도 자동 병합은 하지 않는다.
5. 활성 매핑으로 다시 검증한 결과는 별도 정규화 스테이징 원장에 남긴다.
6. 분개장은 차변·대변 차이가 0원이 아니면 차단한다.
7. 합계잔액시산표는 기간 차변·대변과 기말 차변·대변을 각각 대사한다.
8. 은행거래는 원천 거래 ID 중복과 은행계좌 GL 미연결을 차단한다.
9. 검증 통과는 운영 총계정원장 전기를 의미하지 않는다. 전기 기능은 별도 승인·마감 통제가 마련된 뒤 연다.

## 자료유형별 표준 필드

- 분개장: 전표일, 전표번호, 행번호, 계정코드·명, 거래처, 부서, 적요, 차변, 대변, 원천참조
- 합계잔액시산표: 계정코드·명, 기초 차·대변, 기간 차·대변, 기말 차·대변
- 은행거래: 거래일, 원천계좌 ID, 거래 ID, 적요, 상대방, 입금, 출금, 잔액, 통화

## 통제와 증거

- 매핑 버전 및 활성 버전 고유성
- 결재 요청·결재 결과·매핑 이벤트
- 검증 실행별 건수·매핑률·차대변 합계·차이
- 정규화 행별 원본 체크섬·확인사항
- 관리자 권한 및 ERP 감사 로그

## 다음 단계

검증된 정규화 원장에서 운영 분개 초안을 생성하는 기능은 실제 전표번호 정책, 수정분개 방식, 회계기간 잠금, 세금코드 목록이 확정된 뒤 구축한다.
