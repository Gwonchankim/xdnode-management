# 영업 구글 시트 — 매출 분석·인사이트 기획

## 전제

'26년 매출'(확정)·'진행 딜' 두 탭은 [app/sales-sheet-sync.ts](../app/sales-sheet-sync.ts)로 이미 연동돼 있다
(확정 3,082건·₩441억, 진행 딜 203건·₩172억, 2026-08-26 기준). 지금까지 만든 화면
([app/sales-sheet-sync-view.tsx](../app/sales-sheet-sync-view.tsx), [app/sales-sheet-insights-view.tsx](../app/sales-sheet-insights-view.tsx))은
"동기화됐는지 확인"·"거래처 하나 골라서 이력 보기"·"품질 경고" 수준이지, 매출 데이터 자체를 분석하는 화면은 없다.
이 문서는 그 분석·인사이트 레이어를 기획한다.

## 후보 인사이트

| # | 내용 | 왜 유용한가 | 난이도 |
|---|---|---|---|
| A | **월별 매출 추이** — 확정/진행 딜 막대그래프, 전월 대비 증감률 | 지금은 총합만 보임. 최근 추세(상승/하락)를 한눈에 | 낮음 (Finance의 `FinanceBars` 패턴 재사용) |
| B | **담당자별 실적 순위** — 매출·마진·건수 기준 랭킹 | 누가 잘 하고 있는지, 마진 없이 매출만 밀어붙이는 담당자는 없는지 | 낮음 |
| C | **거래처 집중도** — 상위 N개 거래처가 매출의 몇 %를 차지하는지 | 특정 거래처 의존도가 너무 높으면 리스크 신호 | 낮음 |
| D | **품목·카테고리별 분석** — 어떤 모델이 많이 팔리는지, 마진은 어떤지 | 재고·매입 전략에 참고 | 중간 (품목명이 자유 텍스트라 정규화 필요) |
| E | **마진율 분포** — 평균 마진율, 저마진(예: 5% 미만) 거래 비중 | 박리다매로 매출만 늘고 있는지 확인 | 낮음 |
| F | **수금 현황 확장** — 현재 "데이터 품질 경고"의 지연 건수 외에, 월별 미수금 총액·회수율 추이 | 자금 흐름 파악 | 낮음 (이미 있는 alerts 로직 확장) |
| G | **전환 퍼널** — 인바운드 리드→계약 성공률, 영업보호 등록→확정매출 전환율 | 영업 프로세스 어디서 새는지 확인 (이미 만든 리드 전환 기능·거래처 통합 뷰와 자연스럽게 연결) | 높음 (탭 간 이름 매칭 필요, 완전일치 한계 있음) |

## 방향 제안

**1차로 A·B·C·E**를 묶어 "매출 분석" 화면 하나로 만드는 것을 제안한다 — 전부 매출 원장(`sales_sheet_revenue_records`)
하나만 봐도 계산되고, 서로 자연스럽게 이어진다 (트렌드 → 누가/어디서 그 매출을 만들었는지 → 마진은 건강한지).
사이드바에 "매출 분석" 메뉴를 새로 추가하고 [app/sales-sheet-insights.ts](../app/sales-sheet-insights.ts) 옆에
`app/sales-sheet-analytics.ts`를 만들어 집계 쿼리를 둔다.

**D(품목 분석)**는 품목명이 완전 자유 텍스트라("PRO 6000 Max-Q Workstation Edition"처럼 긴 풀네임, 축약형이 섞여 있음)
정확한 집계를 위해 정규화 규칙이 필요하다 — 이번 1차에서는 원문 그대로 상위 N개만 보여주는 수준으로 하고, 정교한
카테고리 분류는 다음 단계로 미루는 걸 제안한다.

**F(수금 현황 확장)·G(전환 퍼널)**는 이미 있는 기능(품질 경고, 거래처 통합 뷰, 리드 전환)을 확장하는 성격이라
2차로 미루는 걸 제안한다.

## 열린 질문

1. 1차 범위: A·B·C·E 제안대로 진행할지, 우선순위를 다르게 할지?
2. B(담당자별 실적)를 만들면 사실상 개인 성과 랭킹이 노출된다 — 전체 담당자를 다 보여줄지, 본인 것만 보이게 권한을 나눌지?
   (참고: 현재 이 앱의 역할 기반 권한은 `sales:read`/`sales:write` 단위라 담당자 개인별 접근 제한은 없음)
3. 화면 위치: 사이드바에 새 메뉴("매출 분석")로 뺄지, 기존 "구글시트 데이터" 안에 얹을지?

## 결정 및 구현 완료 (2차 포함)

1차(A·B·C·E)에 이어 2차 D·F·G도 모두 구현했다. 전부 `app/sales-sheet-analytics.ts`의 집계 함수 →
`app/api/sales/sheet-sync/analytics/route.ts`(단일 `GET`, `sales:read`) → `app/sales-sheet-analytics-view.tsx`의
패널 8개로 이어진다.

- **D(품목별 실적)** `getItemPerformance`: `TRIM(item)` 원문 그대로 상위 20개, 확정 매출·건수·마진율.
  표기 차이(대소문자, "Retail" 접미사 등)는 이번 단계에서 정규화하지 않음 — 1차 방향 제안 그대로 유지.
- **F(수금 현황)** `getCollectionTrend` + `getCollectionSummary`: `collection_due_date` 월별로 수금 완료/미수금 금액을
  두 막대로 표시, 상단에 전체 수금율·미수금·연체 요약. 기존 데이터 품질 경고(연체 건 리스트)와 상호보완적 —
  경고는 "지금 당장 조치할 개별 건", 이 패널은 "전체 추세".
- **G(전환 퍼널)** `getInboundLeadFunnel` + `getLeadProtectionFunnel`: 각 시트 자체의 결과 필드
  (`final_result`/`progress`)를 1차 신호로 쓰고, 영업보호는 추가로 등록 거래처명이 실제 확정매출 거래처명과
  일치하는 비율(완전일치 기준, `app/sales-sheet-insights.ts`의 계정 매칭과 동일한 한계)을 교차 확인해 노출.

실측 결과(2026-08-27 동기화 기준): 품목 1위 H200(₩101억, 47건), 전체 수금율 81.9%(연체 23건 ₩7.0억),
인바운드 리드 계약 성공률 22.4%(결론 난 건 기준 67.3%), 영업보호 등록 421건 중 WIN 50건이지만 실제 확정매출
거래처명과 일치하는 비율은 9.8%(25/255개사) — 완전일치 한계로 낮게 잡힐 수 있어 참고용 지표로만 사용.
