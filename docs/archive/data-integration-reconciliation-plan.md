# 데이터 연동·대사 센터 기획 및 통제 기준

## 1. 현재 상태 평가

- Clobe 2026 재무와 은행거래는 `erp_sync_runs`에 실행 이력을 남기지만 상태명이 `SUCCESS`와 `SUCCEEDED`로 혼재했다.
- 이카운트 2024–2025, 하이웍스 인원, 급여 Excel은 승인된 스냅샷으로 반영되어 있으나 공통 원천 등록부·예외 검토함·재시도 계보가 없었다.
- 은행거래는 원천 거래 ID를 기본키로 사용하고 현금 대사는 사람의 확정 후 저장하는 안전한 경계가 이미 존재한다.
- 현재 배포 소스에는 Clobe를 실시간 호출하는 커넥터가 없으므로 ‘새 데이터 가져오기’라고 표시하면 안 된다.

## 2. 개선 기획

`erp_sync_runs`를 공통 실행 원장으로 확장하고, 별도의 원천 등록부·예외 원장·append-only 실행 이벤트를 연결한다. 상태는 `RUNNING`, `SUCCEEDED`, `NEEDS_REVIEW`, `FAILED`, `CANCELLED`로 통일하며 과거 `SUCCESS`는 조회 시 `SUCCEEDED`로 호환한다.

동일 원천·실행종류·기준일·체크섬은 멱등키로 중복 생성하지 않는다. 재시도는 원 실행 ID를 `retry_of_run_id`에 보존하고 별도 이벤트를 추가한다.

## 3. 자동화와 사람의 승인 경계

- 자동 검증: 건수, 고유키, 차대변, 미분류, 최신성, 대상 원장 존재 여부를 읽기 전용으로 판정한다.
- 금지: 원천을 자동 덮어쓰기, 자동 삭제, 예외 자동 폐기, 외부 API를 호출하지 않았는데 수집했다고 표시하는 행위.
- 사람의 판단: 담당자 배정, 해결, 위험 수용. 해결·위험 수용은 관리자와 5자 이상 근거, 처리시각을 보존한다.
- 고위험 예외가 남으면 `integration-center-attention` 업무를 생성하며 수동 완료를 차단한다.

## 4. 원천별 대사 기준

- Clobe 재무: 분개장 건수·차변·대변·차이와 배포 기준일.
- Clobe 은행: 원천/D1 건수, 거래 ID 고유성, 미분류 건수.
- 이카운트 2024·2025: 확정 원장 차변·대변 균형. 과거 자료는 일회성 검증 스냅샷으로 유지한다.
- 하이웍스: 승인 파일/D1 인원수, 이메일 중복.
- 급여 Excel: 승인 파일/D1 행수, 원본 시트·행 중복.

## 5. 검증 기준

1. 동일 체크섬 재검증 시 실행 원장이 중복되지 않는다.
2. 재시도는 원 실행 연결을 잃지 않는다.
3. 동일 실행의 동일 예외 키는 중복 생성되지 않는다.
4. 위험 수용 예외는 삭제되지 않고 근거와 이벤트가 남는다.
5. 관리자 외 사용자는 조회·변경할 수 없다.
6. 기존 업무·재무·HR 원장을 자동 변경하지 않는다.
