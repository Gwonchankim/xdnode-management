# 영업 문서 품목·수량·단가 통제 기획

## 현행 평가

- 견적·수주·납품·청구가 총액만 저장되어 무엇을 몇 개, 어떤 단가로 처리했는지 증명할 수 없다.
- 상위 문서와 하위 문서의 연결이 없어 수주량을 초과한 납품·청구를 시스템에서 차단할 수 없다.
- 사용자가 입력한 총액을 신뢰하므로 품목 합계와 문서 총액이 달라질 수 있다.

## 개선된 업무 흐름

1. 상품·서비스 기준정보에 코드, 명칭, 유형, 단위, 기본단가를 등록한다.
2. 견적과 수주는 하나 이상의 품목 라인으로 작성한다.
3. 납품은 승인·완료된 수주 문서를, 청구는 승인·완료된 납품 또는 수주 문서를 근거로 작성한다.
4. 하위 문서 라인은 상위 문서 라인에서 복사하고 처리 수량만 입력한다.
5. 동일 상위 라인에 이미 연결된 미취소 하위 문서 수량을 제외한 잔여 수량까지만 등록한다.
6. 문서 금액은 `수량 × 단가`의 라인별 반올림 합계로 서버가 계산한다.
7. 기존 총액 문서는 마이그레이션 과정에서 임의 품목으로 변환하지 않고 그대로 보존한다.

## 통제 기준

- 품목 코드는 회사 전체에서 유일하고 비활성 품목은 신규 문서에 사용할 수 없다.
- 한 문서 안에서 라인 번호는 유일하다.
- 수량은 0보다 커야 하고 단가는 0 이상이어야 한다.
- 납품은 수주, 청구는 납품 또는 수주만 상위 문서로 선택할 수 있다.
- 상위 문서는 동일 영업기회에 속하고 `ACCEPTED` 또는 `COMPLETED` 상태여야 한다.
- 초과 수량 검증과 하위 문서·라인 저장은 한 번의 DB 처리 묶음으로 수행한다.
- 기준정보와 문서 생성은 영업 권한 및 감사로그를 적용한다.
- 기준정보는 비활성화할 수 있지만 과거 문서 라인의 명칭·단위·단가 스냅샷은 바뀌지 않는다.

## 평가 후 개선사항

- 자유 텍스트 품목 대신 기준정보를 선택해 같은 상품의 표기를 통일한다.
- 사용자가 문서 총액을 직접 입력하지 못하게 하고 읽기 전용 합계로 제시한다.
- 상위 문서를 선택하면 남은 품목과 수량을 화면에 표시한다.
- 과거 총액 문서는 `기존 총액 문서`로 표시해 새 라인 문서와 혼동하지 않는다.
