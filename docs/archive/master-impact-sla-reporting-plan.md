# 기준정보 영향 SLA·에스컬레이션·주간 보고 기획·평가 기록

## 목표

기준정보 차단 업무가 생성된 뒤 장기간 방치되지 않도록 회사 공통 처리기한과 단계별 책임 확인 기준을 적용하고, 관리자별 현재 위험과 주간 스냅샷을 데이터 통제 센터에서 확인한다.

## 1차 기획 평가

최초안은 기한 경과 시 별도의 긴급 업무와 알람을 추가하는 방식이었다. 그러나 차단 업무는 이미 `CRITICAL` 우선순위로 통합 업무함에 등록되므로 같은 문제를 다시 생성하면 중복 알람이 늘고 원천 업무와 완료 상태가 갈라진다. 또한 조직장을 새 담당자로 자동 변경하면 실제 해결 책임과 감사 계보가 훼손될 수 있다.

## 개선안

1. 회사 공통 SLA 정책에 신규 업무의 기본 처리기한, 조직장 확인 단계, 경영 책임자 확인 단계를 저장한다.
2. 기한 경과 단계가 높아질 때 기존 차단 업무에 `SLA_ESCALATED` 이벤트를 한 번만 추가한다.
3. 원 담당자와 기한을 자동 변경하지 않고 조직장·경영 책임자가 확인해야 하는 위험 수준만 표시한다.
4. 담당자의 인사기록에 등록된 조직장을 기준으로 활성·기한 경과·단계별 위험을 집계한다.
5. 현재 정책, 관리자 집계, 활성 업무의 핵심 수치와 체크섬을 주간 스냅샷으로 저장한다.

## SLA 정책

- 기본값은 신규 차단 업무 3일, 기한 1일 경과 시 조직장 확인, 3일 경과 시 경영 책임자 확인이다.
- 기본 처리기한은 1~30일, 조직장 확인은 1~14일 범위로 제한한다.
- 경영 책임자 확인 시점은 조직장 확인보다 늦고 30일 이내여야 한다.
- 정책 변경은 낙관적 버전 검사를 거치며 통합 감사 로그에 남긴다.
- 정책 변경은 새로 생성되는 업무에만 적용하고 기존 업무의 담당자·기한을 소급 변경하지 않는다.

## 에스컬레이션 통제

- 해결·재배정·종결은 자동으로 수행하지 않는다.
- 에스컬레이션 수준은 하향하지 않으며, 기한을 연장하더라도 과거 위험 이력을 보존한다.
- 동일 단계는 조건부 갱신으로 한 번만 기록해 동시 조회에서도 중복 이벤트를 만들지 않는다.
- 모든 단계 상향은 append-only 사건 원장과 통합 감사 로그에 남긴다.
- 실제 업무 종결은 기존과 동일하게 원장 재검증 통과와 해결 메모·증빙을 요구한다.

## 주간 보고

- 보고는 사용자가 명시적으로 저장하며 자동으로 사실을 생성하지 않는다.
- 같은 주에 다시 저장하면 기존 보고를 덮어쓰지 않고 새 버전을 추가한다.
- 보고에는 기준일, 적용 정책 버전, 활성·기한 경과·단계별 수치, 관리자별 집계, 개별 차단 업무 핵심 값과 SHA-256 체크섬을 동결한다.
- 저장된 보고를 수정하거나 삭제하는 API는 제공하지 않는다.

## 완료 기준

- 데이터 통제 센터에서 SLA 정책을 수정하고 새 업무 기한에 적용할 수 있다.
- 기한 경과 단계가 중복 없이 자동 계산되고 처리 이력에 남는다.
- 관리자별 위험 집계와 단계 표시를 확인할 수 있다.
- 같은 주의 주간 보고가 버전별 불변 스냅샷으로 보존된다.
- 권한, 동시성, 범위 검증, 마이그레이션, 인덱스, 회귀 테스트와 운영 빌드가 통과한다.
