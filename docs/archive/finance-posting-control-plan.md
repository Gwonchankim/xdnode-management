# 재무 분개 전기 통제 기획

## 평가

기존 `finance_journal_entries`는 승인된 지급요청 하나를 차변·대변 한 쌍으로 기록하기 위한 원장이다. 외부 분개장처럼 하나의 전표가 여러 행을 갖는 자료를 여기에 넣으면 전표 균형, 원천 행, 세금 검토와 수정분개 연결이 손실된다.

## 개선 기획

- 기존 지급전표 원장은 보존한다.
- 검증 상태가 `PASSED`인 분개장 정규화 원장만 다행 분개 초안으로 만든다.
- 합계잔액시산표는 개시잔액 승인 절차가 필요하고 은행거래는 분류·대사가 필요하므로 자동 분개 대상에서 제외한다.
- 원천의 계정·금액·전표일·전표번호는 초안에서 수정하지 않는다. 오류는 원천 정정 후 새 검증으로 처리한다.
- 모든 행은 세금코드를 선택하거나 해당 없음 사유를 기록해 검토 완료해야 한다.
- 각 원천 전표와 전체 배치는 차변·대변 차이가 0원이어야 결재 제출할 수 있다.
- `finance_close_runs.status = CLOSED`인 기간은 초안 생성·결재 제출·전기를 모두 차단한다. 현재 월이 아닌데 마감 원장 자체가 없는 기간도 미개방으로 차단한다.
- 최종 승인 후에도 사용자가 전기 버튼을 눌러야 하며, 전기 직전에 잔액·계정·세금코드·마감 상태를 다시 검증한다.
- 전기된 전표는 수정·삭제하지 않는다. 정당한 사유와 열린 기간을 지정해 차변·대변을 뒤집은 수정분개 배치를 생성하고 같은 결재·전기 절차를 거친다.
- 월마감은 해당 월과 겹치는 `DRAFT`, `SUBMITTED`, `APPROVED` 분개 배치를 자동 통제로 집계한다. 하나라도 남아 있으면 마감 결재 제출을 차단하며 `REJECTED`, `POSTED` 배치는 대기 건으로 세지 않는다.

## 번호와 중복

- 가져온 전표번호는 `IMP-{원천}-{전표일}-{원천전표번호}` 형식의 결정적 운영 번호로 변환한다.
- 수정분개는 `REV-{기간}-{원전표번호}`를 사용한다.
- 검증 실행, 원천 행, 원전표번호, 수정분개 원전표는 데이터베이스 고유 제약으로 중복을 차단한다.

## 원장

- `finance_posting_batches`: 검증·결재·전기·수정분개 배치
- `finance_posting_vouchers`: 원천 전표별 균형과 운영 전표번호
- `finance_posting_lines`: 계정·거래처·부서·세금 검토·원천 행 계보
- `finance_posting_events`: 생성·세금검토·제출·승인·전기·수정분개 이벤트

## 검증 증거

- 원천 검증이 `PASSED`이며 자료유형이 `JOURNAL`
- 모든 전표와 배치의 차변·대변 차이 0원
- 모든 행 세금 검토 완료
- 활성 계정과목과 활성 세금코드만 참조
- 대상 기간 미마감
- 최종 전자결재 승인 및 사용자 전기 확인
