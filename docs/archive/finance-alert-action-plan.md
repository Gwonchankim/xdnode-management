# 재무 경보 조치 통제 기획서

## 1. 평가

기존 통합 업무함은 일반 알림과 재무 시스템 경보를 동일한 `완료 처리` 버튼으로 닫을 수 있었다. 따라서 원인, 재무 영향, 담당자, 기한, 조치계획, 근거자료와 승인자가 남지 않아 중요 경보의 해결 여부를 사후 검증하기 어려웠다.

## 2. 개선 원칙

- 수기 일반 알림은 기존처럼 간단히 완료할 수 있다.
- `finance + SYSTEM_RULE` 경보만 조치 통제 대상이다.
- 조치 통제 대상은 `OPEN → IN_PROGRESS → REVIEW → CLOSED` 흐름을 따른다.
- 동일 업무와 동일 원천 버전에는 하나의 조치 원장만 생성한다.
- 같은 규칙이 새 원천 버전에서 다시 발생하면 새 사례로 관리한다.
- 모든 상태 변경은 별도 이벤트 원장에 추가 기록하며 기존 이력을 덮어쓰지 않는다.

## 3. 역할과 권한

- 재무 조회 권한: 사례, 처리 이력, 근거자료 조회
- 재무 쓰기 권한: 담당자·기한·원인·영향·조치계획 저장 및 종료 검토 요청
- 재무 승인 권한: 종료 승인, 보완 요청, 종료 사례 재개방
- 회사에 등록된 직원만 조치 담당자로 지정

## 4. 종료 통제

종료 검토 요청에는 다음 항목이 모두 필요하다.

1. 조치 담당자와 기한
2. 원인 분석
3. 재무 영향 평가
4. 실행 가능한 조치 계획
5. 최소 1개의 근거자료

종료 승인에는 조치 결과와 잔여 위험을 설명한 종료 요약이 필요하다. 승인 전에는 원본 업무를 `DONE`으로 바꿀 수 없다. 검토 또는 종료 단계의 근거자료는 감사 이력 보호를 위해 추가·삭제할 수 없다.

## 5. 화면 흐름

- 상단 통합 업무함의 중요 재무 경보는 `완료 처리` 대신 `조치 등록`으로 이동한다.
- 재무 사이드바의 `재무 경보 조치`에서 상태별 현황과 사례 목록을 본다.
- 사례 상세에서 원인 화면 이동, 담당자·기한 지정, 분석·계획 작성, 근거 첨부, 검토 요청을 수행한다.
- 관리자는 종료 승인 또는 사유가 있는 보완 요청을 수행한다.
- 종료 후 새 사실이 확인되면 재개방하여 후속 조치를 기록한다.

## 6. 수용 기준

- 중요 재무 경보를 통합 업무함에서 직접 완료할 수 없어야 한다.
- 증빙이나 필수 분석이 없으면 검토 요청이 거부되어야 한다.
- 재무 승인 권한이 없는 사용자는 종료·반려·재개방할 수 없어야 한다.
- 종료 승인과 업무 완료가 함께 반영되어야 한다.
- 새로고침 후 사례 상태, 담당자, 입력 내용, 증빙, 이력이 유지되어야 한다.
- 동일 업무·동일 원천 사례가 중복 생성되지 않아야 한다.
- 기존 일반 알림 처리 방식과 다른 모듈 업무는 영향을 받지 않아야 한다.
