# 경영보고 의사결정 원장 기획·평가

## 1. 평가

- 월간 경영보고에는 의사결정 요청 문안과 후속조치 원장이 있지만, 어떤 안건이 승인·보류·반려되었는지 구조적으로 남지 않는다.
- 보고서 승인과 안건 결정을 같은 의미로 처리하면 보고 수치의 승인과 경영 판단을 혼동한다.
- 자유문장을 바로 업무로 복사하면 담당자·기한·결정 근거가 누락되거나 같은 업무가 중복 생성될 수 있다.

## 2. 개선된 정책

1. 보고서 초안에서 안건을 `예산·자금·영업·인사·위험·정책·기타` 유형과 원천 구간으로 등록한다.
2. 안건에는 요청 내용, 예상 재무영향, 결정 책임자, 결정기한과 후속조치 필요 여부를 저장한다.
3. 보고서를 제출하면 안건은 `DRAFT → PENDING`으로 잠기며, 결재가 반려되면 다시 `DRAFT`로 돌아간다.
4. 보고서가 승인된 뒤 재무 승인 권한자만 안건을 `APPROVED·DEFERRED·REJECTED` 중 하나로 확정한다.
5. 후속조치가 필요한 승인·보류 안건은 한 번만 경영회의 후속조치 원장으로 전환하고 안건과 조치 ID를 상호 추적한다.
6. 승인본의 보고 수치와 문안은 변경하지 않고, 안건 결정 결과와 실행 상태는 별도 운영 원장에 누적한다.
7. 미결정 안건이 남은 승인본은 개정할 수 없게 하여 안건이 대체 버전에 묻히거나 중복 복제되지 않도록 한다.
8. 승인된 보고서의 미결정·기한경과 안건은 통합 업무와 알림에 노출한다.

## 3. 상태와 통제

- 안건: `DRAFT → PENDING → APPROVED | DEFERRED | REJECTED`
- 보고서 제출 실패 또는 결재 반려 시 `PENDING → DRAFT`
- `APPROVED·DEFERRED`에서 후속조치 필요가 선택된 경우 담당자와 기한이 반드시 있어야 한다.
- 안건 하나에는 자동 생성 후속조치가 최대 한 건만 연결된다.
- 결정 메모는 5자 이상이며 결정자·결정일시와 함께 감사기록에 남긴다.

## 4. 검증 기준

- 제출 전 안건만 수정·삭제할 수 있어야 한다.
- 승인되지 않은 보고서의 안건은 결정할 수 없어야 한다.
- 같은 안건을 반복 확정해도 후속조치가 중복 생성되지 않아야 한다.
- 결재 반려 시 안건이 다시 편집 가능 상태가 되어야 한다.
- 개정본은 기존 승인본의 미결정 안건을 복제하지 않아야 한다.
- 기존 경영보고와 후속조치 데이터는 새 필드 없이도 그대로 조회되어야 한다.
