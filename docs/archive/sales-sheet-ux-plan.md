# 영업 구글 시트 데이터 — 화면 구성·UX·추가 기능 기획

## 현재 상태의 한계

[docs/sales-sheet-integration-plan.md](sales-sheet-integration-plan.md)로 7개 표(매출 원장·영업보호·인바운드 영업·
서버납품·AS·매입단가고지)를 실제로 반영하는 데는 성공했지만, 지금의 [app/sales-sheet-sync-view.tsx](../app/sales-sheet-sync-view.tsx)는
"동기화가 됐는지 확인하는" 용도에 가깝다. 실제로 영업파트가 매일 쓰기엔 아래 문제가 있다.

1. **한 화면에 다 몰려 있음**: 이미 길게 스크롤되는 `sales-workspace.tsx`(거래처·영업기회·목표전망·카탈로그·문서·인센티브) 맨 위에
   7개 구획이 통째로 추가돼 있다. 찾고 싶은 표까지 스크롤이 길다.
2. **검색·필터 없음**: 매출 원장만 3,285건인데 최근 50건만 보여준다. 고객사·담당자·기간으로 좁혀볼 방법이 없다.
3. **표끼리 연결이 안 됨**: 같은 고객사가 영업보호(선점권 등록) → 인바운드 영업(문의) → 진행 딜/확정 매출 → 서버납품 →
   AS까지 이어지는데, 지금은 5개 표가 완전히 따로 논다. 한 고객사의 전체 이력을 보려면 표 5개를 각각 열어 눈으로 대조해야 한다.
4. **데이터 품질 신호가 없음**: 수금예정일이 지났는데 수금이 안 된 건, 오래 정체된 진행 딜 같은 "지금 챙겨야 할 것"이
   화면에 전혀 드러나지 않는다.
5. **동기화가 전부-아니면-전무**: 버튼 하나로 7개를 한꺼번에 동기화한다. 특정 표만 다시 불러오거나, 마지막 동기화가
   언제였는지 한눈에 보기 어렵다.

## 방향 후보

### A. 화면 구성
- **A1. 서브 내비게이션 도입**: 영업 화면 상단에 `개요 | CRM | 구글시트 데이터 | 카탈로그 | 문서` 같은 탭을 두고, 시트
  데이터를 별도 화면으로 분리. 스크롤 부담이 줄고, 이후 Phase 3(GPU가격표 등) 추가도 여기 안에 쌓인다.
- **A2. 지금처럼 한 화면에 이어붙이되 구획을 접고 펴는 아코디언으로**: 구조 변경이 적어 구현이 가장 빠르다.

### B. 검색·필터
전체 표 공통으로 고객사/담당자/제품명 텍스트 검색 + 기간 필터. 서버 쪽에서 `LIKE` 검색과 페이지네이션을 붙이면 된다
(현재는 무조건 최근 50건만 반환).

### C. 거래처 통합 뷰 (교차 연결)
고객사 이름을 누르면 그 고객사와 관련된 선점권 등록·인바운드 문의·매출·납품·AS 이력을 시간순으로 한 화면에서 본다.
가장 체감 효과가 클 항목이지만, 시트의 고객사명이 완전한 자유 텍스트라(정규화된 ID 없음) 이름이 살짝 다르게 적힌
같은 고객사를 얼마나 정확히 묶을지 설계가 필요하다 (완전 일치만 묶을지, 유사 매칭까지 할지).

### D. 데이터 품질 경고
- 수금예정일이 지났는데 수금일이 비어 있는 매출 건
- 등록 후 오래(예: 30일+) 정체된 진행 딜·인바운드 리드
- 이번 동기화에서 갑자기 크게 줄어든 표(원본에서 대량 삭제/이동 가능성) 감지해 배지로 노출

### E. CRM 수동 연동
"자동 승격은 하지 않는다"는 기존 결정은 유지하되, 화면에서 사람이 클릭해 인바운드 리드를 `sales_opportunities`
영업기회로 전환하는 버튼을 추가하는 옵션. 전환 시 어떤 필드를 어떻게 매핑할지 규칙 설계가 필요하다.

### F. 내보내기
매출/리드 등을 엑셀로 내보내기 (기존 코드베이스에 `write-excel-file` 사용 사례 있음, [compensation-calculator.tsx](../app/compensation-calculator.tsx) 참고).

### G. 동기화 UX 개선
- "마지막 동기화 3시간 전" 같은 경과 배지
- 표 하나만 골라 재동기화하는 버튼 (현재는 전체 7개 일괄만 가능)
- 최근 동기화 이력(성공/실패) 타임라인

## 결정 및 구현 완료

- 화면 구성: **A1** (서브 내비게이션). [app/sales-workspace.tsx](../app/sales-workspace.tsx)에 "영업 운영 | 구글시트 데이터" 탭을 추가했다.
- 우선순위: **C(거래처 통합 뷰) → B(검색·필터) → D(데이터 품질 경고)** 순으로 구현.
- C의 고객사명 매칭은 **완전 일치(trim)만** — 실제로 "한국과학기술원"과 "한국과학기술원 전기 및 전자공학과" 같은
  학과 단위 변형이 시트에 많아, 다르게 적힌 걸 자동으로 묶었다면 오히려 부정확했을 것.

**구현**: [app/sales-sheet-insights.ts](../app/sales-sheet-insights.ts)(교차 조회) · [app/sales-sheet-insights-view.tsx](../app/sales-sheet-insights-view.tsx)(거래처 통합 뷰 + 데이터 품질 경고 화면) ·
[app/api/sales/sheet-sync/insights/route.ts](../app/api/sales/sheet-sync/insights/route.ts) · 기존 동기화 라우트에 `?q=` 검색 파라미터 추가
([app/sales-sheet-sync-kit.ts](../app/sales-sheet-sync-kit.ts)의 `searchSheetRecords`).

실제 데이터로 확인: 수금 지연 18건 · 30일+ 정체 진행 딜 48건 · 30일+ 무응답 인바운드 리드 50건 감지.
(첫 구현 때 `수금예정일`이 "11월중" 같은 자유 텍스트인 행이 문자열 비교로 오탐되는 버그가 있어 ISO 날짜 형식(`GLOB`)
검증을 추가해 고쳤다.)

## E/F/G 구현 완료

- **G. 동기화 UX**: 경과시간 배지("3시간 전" 등), 표별 "이 표만 재동기화" 버튼, 최근 동기화 이력 타임라인(성공/실패 20건).
  ([app/sales-sheet-sync-kit.ts](../app/sales-sheet-sync-kit.ts)의 `getRecentSyncRuns`, `sales_sheet_sync_runs.sync_key`로 파이프라인별 이력 구분)
- **F. 엑셀 내보내기**: 현재 화면(검색 필터 반영)의 매출 원장 + 5개 탭을 시트별로 나눠 `write-excel-file/browser`로 즉시 다운로드.
- **E. 리드→영업기회 전환**: [app/sales-sheet-lead-conversion.ts](../app/sales-sheet-lead-conversion.ts) — 인바운드 영업 탭에서 리드별 "영업기회로 전환" 버튼.
  일치하는 **활성 거래처가 이미 등록돼 있어야만** 전환되고(자동 거래처 생성 없음 — 재무 마스터데이터 연동까지 얽혀 있어 위험), 없으면
  "먼저 '<회사명>' 거래처를 영업 운영 화면에서 등록해 주세요" 안내. 전환 이력은 `sales_sheet_lead_conversions`에 남아 중복 전환을 막는다.

실제 데이터로 3가지 시나리오(회사명 없음 → 거절 / 미등록 거래처 → 안내 / 등록된 거래처 → 성공) 전부 확인.
검증 중 만든 테스트용 거래처 "Toronntech trading llc"와 연결 영업기회·마스터데이터 연동 레코드는 확인 후 전부 삭제했다
(erp_audit_logs에 정리 사유 기록).
