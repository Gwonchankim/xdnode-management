# 통제형 데이터 수집·승인·반영 기획

## 현재 상태 평가

- ERP는 R2 문서 원본 보관, D1 감사기록, 전자결재 기능을 이미 갖췄다.
- 외부 파일을 업무 원장에 반영하기 전 행 단위 검증·중복 판정·변경 미리보기·승인 단계를 공통으로 관리하는 원장은 없었다.
- 원천별 파일 구조가 다르므로 범용 업로드가 곧바로 업무 원장을 수정하면 잘못된 열 매핑과 대량 덮어쓰기 위험이 생긴다.

## 개선된 처리 흐름

1. 관리자가 등록 원천과 CSV·JSON·XLSX 파일을 선택한다.
2. 원본 바이트는 변경하지 않고 R2에 보관하며 SHA-256을 계산한다.
3. 동일 원천·동일 체크섬은 중복 등록하지 않는다.
4. 최대 500행을 스테이징하여 원본 JSON, 정규화 JSON, 식별키, 행 체크섬, 검증 오류와 처리 예정값을 보존한다.
5. 사용자는 정상 행의 신규·수정·제외 여부를 검토한다. 오류 행은 제외만 가능하며 원본 파일을 수정해 다시 올리는 것이 원칙이다.
6. 전자결재 최종 승인 전에는 업무 원장을 변경하지 않는다.
7. 승인 후에도 자동 반영하지 않는다. 관리자가 `승인본 반영`을 눌러야 한 번의 D1 배치로 반영된다.
8. 업로드·행 검토·결재·반영은 감사기록과 append-only 이벤트에 남는다.

## 원천별 적용 범위

- 하이웍스 임직원: 이름·이메일 필수 검증, 이메일/사번 식별, 인사기록 신규·수정.
- 급여 Excel: 급여월·직원명 필수 검증, 원본 시트·행을 포함한 식별키, 급여 원장 신규·수정.
- Clobe·이카운트 재무: 원본 보관과 행 검증·결재까지 제공한다. 실제 업무 원장 반영은 API 계약과 계정 매핑이 확정될 때까지 차단한다.

## 안전장치

- 관리자 권한 전용, 파일 10MB·500행 제한.
- 원본 자동 삭제 없음, 업무 원장 자동 반영 없음.
- 승인 배치만 반영 가능하며 반영 완료 배치는 재실행할 수 없다.
- 반영 SQL은 허용된 두 원천에만 고정된 열 목록을 사용한다.
- 빈 선택값이 기존 인사기록의 주요 값을 지우지 않도록 선택적 갱신한다.
- 급여는 결정적 ID로 upsert하여 동일 지급행의 이중 생성을 차단한다.

## 검증 기준

- 마이그레이션이 기존 전체 스키마와 함께 적용된다.
- 동일 원천·체크섬과 동일 배치·행 번호가 DB 제약으로 차단된다.
- 승인 전 반영, 오류 행 강제 반영, 지원하지 않는 재무 원천 반영이 차단된다.
- 승인 결과가 수집 배치에 연결되고 이벤트가 보존된다.
- 반영 완료 시 실행 원장과 감사기록이 생성된다.
