# 전사 기준정보 영향 해결 큐 기획·평가 기록

## 목표

기준정보 변경 영향도에서 발견한 실제 차단 항목을 담당자, 기한, 재검증, 증빙이 있는 운영 업무로 연결한다. 영향도 확인 화면에서 끝나는 것이 아니라 원천 원장이 정리될 때까지 전사 데이터 통제 센터에서 추적한다.

## 기획 평가와 개선

최초안은 모든 영향도 결과를 업무로 등록하는 방식이었다. 그러나 주의·참고 항목까지 자동 업무화하면 같은 대상을 여러 번 조회할 때 업무가 급증하고 중요한 차단 항목이 묻힌다. 개선안은 다음과 같다.

1. `BLOCKER`이면서 연결 건수가 1건 이상인 항목만 자동 등록한다.
2. 같은 대상·작업·영향 코드의 미종결 업무는 하나만 유지하고 새 평가 결과로 현재 수치와 원천 평가를 갱신한다.
3. 주의·참고 항목은 영향도 평가 기록에만 보존하며 해결 큐에는 만들지 않는다.
4. 자동 해결, 자동 계정 치환, 자동 병합, 자동 종결은 하지 않는다.

## 상태와 종결 통제

상태는 `OPEN → IN_PROGRESS → VERIFIED → CLOSED` 순서로 진행한다.

- `OPEN`: 차단 항목이 생성됐고 해결 작업을 시작하지 않은 상태다.
- `IN_PROGRESS`: 담당자가 연결 원장을 정리하고 있는 상태다.
- `VERIFIED`: 서버가 동일한 실제 운영 원장을 다시 계산해 해당 차단 건수가 0임을 확인한 상태다.
- `CLOSED`: 재검증 통과 후 10자 이상의 해결 메모와 증빙 참조를 기록한 상태다.

재검증에서 차단 건수가 남으면 `VERIFIED`로 전환하지 않는다. 종결 뒤 같은 문제가 다시 발견되면 과거 이력은 유지하고 새 업무를 만들 수 있다.

## 담당자와 업무 원장

- 담당자는 `hr_employee_records`에 등록된 재직 중 회사 직원만 선택한다.
- 기한은 오늘보다 과거로 지정할 수 없다.
- 차단 업무 생성과 동시에 `erp_tasks`에 `MASTER_IMPACT_CASE` 원천 업무를 연결한다.
- 해결 큐의 담당자·기한·종결 상태는 연결 업무 원장에도 동기화한다.
- 해결 큐가 종결되기 전에는 연결 업무를 완료로 표시하지 않는다.

## 감사와 동시성

- 생성, 원천 갱신, 배정, 시작, 재검증, 종결은 append-only 이벤트로 남긴다.
- 상태 변경은 예상 버전을 전달하는 낙관적 동시성 제어를 사용한다.
- 모든 관리 작업은 `settings:admin` 권한이 필요하고 통합 감사 로그에도 남긴다.
- 화면의 상태나 브라우저 저장소는 판단 근거로 사용하지 않는다.

## 완료 기준

- 데이터 통제 센터에 기준정보 영향 탭과 요약·검색·상태 필터가 제공된다.
- 실제 차단 항목만 중복 없이 자동 업무화된다.
- 재검증을 통과하지 않은 업무를 종결할 수 없다.
- 해결 메모와 증빙이 없으면 종결할 수 없다.
- 마이그레이션, 권한 검사, 중복 방지, 상태 전이, 전체 회귀 테스트와 운영 빌드가 통과한다.
