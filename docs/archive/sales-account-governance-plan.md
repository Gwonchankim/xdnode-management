# 거래처 마스터·고객 360도 기획 및 평가

## 1. 기획 목표

- 사업자번호가 있으면 사업자번호, 없으면 정규화한 거래처명을 기준으로 신규 중복을 차단한다.
- 거래처 수정, 비활성화, 병합, 영업 담당자 이관을 모두 감사 가능한 원장으로 남긴다.
- 거래처 한 화면에서 고객 담당자, 영업기회, 접점 활동, 견적·수주·청구·수금, 미수금과 담당 이력을 확인한다.
- 담당자 공백, 장기 미접촉, 기존 중복 후보를 운영 알림으로 승격한다.

## 2. 현행 평가

| 영역 | 현행 | 위험 | 개선 판단 |
|---|---|---|---|
| 거래처 식별 | 이름·사업자번호 원문만 저장 | 띄어쓰기·하이픈 차이로 중복 등록 | 별도 식별키 원장과 DB 유일성 필요 |
| 담당자 이관 | 거래처·기회에 담당자만 저장 | 변경 이유·이전 담당자 추적 불가 | 이관 이력과 진행 기회 동시 이관 필요 |
| 고객 담당자 | 거래처별 연락처 저장 | 대표 담당자 복수 지정 가능 | 활성 대표 담당자 1명 DB 제약 필요 |
| 거래처 삭제 | 기능 없음 | 잘못 만든 거래처 정리 불가 | 거래가 있는 경우 삭제보다 병합·비활성화 |
| 고객 조회 | 영업기회 단위 CRM | 미수·문서·접점이 여러 화면에 분산 | 거래처 단위 360도 화면 필요 |
| 재무 연계 | 영업 등록 시 재무 거래처 별칭 생성 | 영업 병합이 재무 원장을 암묵 변경할 위험 | 재무 마스터 병합은 별도 승인으로 분리 |

## 3. 개선된 통제 설계

1. `sales_account_identity_keys`가 정규화된 식별키를 독점한다. 기존 중복은 자동 삭제하지 않고 후보로 표시한다.
2. 비활성화는 진행 중 영업기회나 미수금이 없을 때만 허용한다.
3. 병합은 영업 삭제 권한과 10자 이상 사유가 필요하다. 영업기회·고객 담당자는 대상 거래처로 이동하고 활동 이력은 보존한다.
4. 연락처 충돌 시 동일 연락처는 하나로 연결하고, 과거 활동의 연락처 참조를 대상 연락처로 치환한다.
5. 담당자 이관은 재직 중인 직원만 선택할 수 있고, 거래처와 진행 중 영업기회를 한 트랜잭션으로 이관한다.
6. 고객 360도에는 원본 금액을 수정하는 기능을 넣지 않는다. 미수금은 청구·확정 수금 원장에서 계산한다.
7. 재무 거래처 마스터 병합은 영업 병합과 분리한다. 자동으로 재무 원장을 합치지 않고 감사 기록만 남긴다.

## 4. 검증 기준

- 같은 식별키의 신규 거래처는 HTTP 409로 거절된다.
- 활성 대표 담당자는 거래처당 최대 1명이다.
- 이관 후 거래처와 진행 영업기회의 담당자가 같고 이력이 남는다.
- 진행 영업기회 또는 미수금이 있는 거래처는 비활성화되지 않는다.
- 병합 후 원천 거래처는 조회 목록에서 제외되고, 기회·연락처·활동·문서 연결은 보존된다.
- 고객 360도 미수금 합계는 확정 청구액에서 확정·완료 수금 배분액을 뺀 값과 같다.
- 운영 알림에서 담당자 공백, 30일 이상 미접촉, 기존 중복 후보가 확인된다.
