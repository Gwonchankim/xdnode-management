# 데이터 신뢰성·백업·감사 통제 기획

## 1. 기획

실제 인사·급여·재무 자료가 저장되는 ERP에서 다음 질문에 관리자 화면이 근거로 답하도록 한다.

- 핵심 테이블과 최고관리자 접근이 정상인가?
- 감사기록과 외부 연동 자료는 최신이며 조회 가능한가?
- 문서·면담 녹음의 DB 메타데이터와 R2 원본이 함께 존재하는가?
- D1 업무 데이터를 논리 스냅샷으로 보존하고 원본 변조 여부를 검증할 수 있는가?
- 운영 DB에 쓰지 않고 복구 가능성을 모의 점검했는가?
- 데이터 유형별 보존기간이 관리자에게 확정되었는가?
- 특정 기간의 감사기록을 재현 가능한 파일로 내보낼 수 있는가?

## 2. 평가

초기 구상인 `전체 백업 + 원클릭 자동 복구 + 만료 데이터 자동 삭제`는 다음 위험이 있다.

- 배포 환경에서 D1 전체 물리 백업을 애플리케이션 코드가 완전하게 대체한다고 보장할 수 없다.
- 현재 스키마와 과거 스냅샷 스키마가 다르면 자동 복구가 최신 데이터를 손상할 수 있다.
- 인사·급여·감사기록의 보존기간은 회사 정책과 법률 검토 없이 자동 확정하면 안 된다.
- R2의 문서·녹음 원본과 D1 메타데이터는 복구 단위가 다르다.
- 백업 파일이 존재하는 것만으로는 해시·구조·행 수가 정상인지 증명되지 않는다.

## 3. 개선된 기획안

### D1 논리 스냅샷

- 애플리케이션 테이블의 생성 SQL과 행 데이터를 JSON으로 보존한다.
- 데이터 통제 자체의 실행·스냅샷·내보내기 원장은 스냅샷에서 제외해 재귀 증가를 막는다.
- SHA-256, 바이트 수, 테이블 수, 행 수와 표 목록을 D1 원장에 기록한다.
- 생성 전후 감사기록 건수와 최신 시각을 비교해 동시 업무 변경이 감지되면 스냅샷을 폐기한다.
- 한 실행은 50,000행·20MB 안전 한도를 넘지 않으며, 초과 시 실패를 숨기지 않는다.
- 스냅샷 원본은 R2의 별도 접두어 아래 저장한다.

### 검증 및 복구 모의훈련

- 검증은 R2 원본을 다시 읽어 SHA-256, 포맷, 테이블 수, 행 수를 대조한다.
- 복구 모의훈련은 테이블 이름·스키마·행 배열 구조를 확인한다.
- 모의훈련은 운영 D1에 데이터를 쓰지 않으며 `productionWrites: 0`을 결과에 남긴다.
- 실제 복구는 자동 제공하지 않는다. 장애 시 검증된 파일과 당시 마이그레이션을 기준으로 별도 승인 절차를 거친다.

### 운영 무결성 점검

- 핵심 테이블, 활성 최고관리자, 직원 이메일 중복, 감사기록, 외부 연동 최신성
- 2026 분개장 차대변, 최근 문서·면담 녹음 R2 원본 표본
- 최근 검증 스냅샷과 보존정책 확정 상태
- 각 결과는 `PASS`, `WARN`, `FAIL`; 실행 전체는 `HEALTHY`, `ATTENTION`, `CRITICAL`로 동결한다.
- `WARN` 또는 `FAIL`이 있으면 통합 업무함에 데이터 통제 업무를 열고 센터로 직접 이동시킨다.
- 이 시스템 업무는 수동 완료할 수 없고 후속 점검이 `HEALTHY`가 되면 자동 종료한다.

### 감사 내보내기

- 최고관리자만 기간·모듈 기준 CSV를 생성·다운로드한다.
- 행위의 변경 전후 JSON은 내보내지 않고 사용자·시각·행위·대상·사유만 포함한다.
- 한 파일은 최대 1년·10,000건이며 SHA-256과 행 수를 원장에 남긴다.
- 파일 생성과 다운로드 자체도 감사기록에 기록한다.

### 보존정책

- 감사·인사·급여·면담녹음 유형별 보존일을 설정한다.
- 초기값은 모두 미확정이다.
- 정책을 확정해도 자동 삭제하지 않고 `REVIEW_REQUIRED`만 적용한다.

## 4. 권한과 감사

- 조회·점검·스냅샷·검증·모의훈련·내보내기·정책 변경은 모두 `settings:admin` 전용이다.
- 생성, 검증, 모의훈련, 다운로드, 정책 변경은 `erp_audit_logs`에 남긴다.
- 스냅샷 원본과 감사 CSV 응답은 `private, no-store`로 내려받는다.

## 5. 검증 기준

- 신규 마이그레이션이 빈 SQLite에서 적용되고 유일성·인덱스가 유지된다.
- 최고관리자가 아닌 역할은 데이터 통제 API를 실행할 수 없다.
- 스냅샷은 자체 통제 원장을 포함하지 않으며 안전 한도를 강제한다.
- 해시 또는 구조가 다르면 검증을 통과하지 않는다.
- 복구 모의훈련에는 운영 DB 쓰기가 없다.
- 보존정책 변경은 자동 삭제로 이어지지 않는다.
- 감사 CSV는 기간·모듈·행 수 제한을 지킨다.
- 전체 빌드와 기존 회귀검증이 통과한다.
