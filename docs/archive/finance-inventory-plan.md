# 재고·상품원가 통제 기획

## 1. 현행 평가

- 구매는 발주 품목과 입고·검수 수량까지 저장하지만 상품코드와 창고가 없다.
- 영업은 납품 문서를 저장하지만 품목·수량이 없어 출고 재고와 연결되지 않는다.
- 재무 대시보드의 매출·매입 차이는 재고자산과 매출원가를 반영하지 않으므로 이익이 아니다.
- 기존 자유입력 품목명을 자동으로 같은 SKU라고 간주하면 서로 다른 규격을 합칠 수 있다.

## 2. 개선된 기획

1. 상품과 창고는 별도 마스터로 생성·수정·비활성 관리하며 SKU와 창고코드는 각각 중복될 수 없다.
2. 재고 원장은 수정·삭제하지 않는 이동 원장으로 저장한다. 정정은 반대 조정 이동을 추가한다.
3. 입고는 승인된 입고·검수의 합격수량만 후보로 보여주고 사용자가 상품·창고를 명시적으로 연결한다.
4. 같은 입고검수 행은 한 번만 재고에 반영한다.
5. 출고는 확정·완료된 납품 문서에만 연결하고 현재 가용수량보다 많이 출고할 수 없다.
6. 재고조정은 사유가 필수이며 입고조정은 단가를 입력하고 출고조정은 현재 이동평균 원가를 사용한다.
7. 재고가치는 입고 원가와 출고 당시 이동평균 원가의 순액으로 계산한다. 과거 Clobe·이카운트 자료를 임의로 재고수량으로 환산하지 않는다.
8. 안전재고 미달과 아직 상품·창고에 연결되지 않은 입고검수 행을 상태 기반 알림과 월마감 통제로 연결한다.
9. 입고 이동일은 원천 입고일을 사용하며 잠긴 마감월에는 입고·출고·조정을 추가할 수 없다.

## 3. 화면

- 요약: 총 재고가치, 보유 SKU, 안전재고 미달, 미반영 입고
- 현재고: SKU, 상품명, 창고, 수량, 이동평균 원가, 재고가치, 안전재고 상태
- 입고 반영: 미반영 입고검수 행, 상품, 창고
- 출고·조정: 납품 문서 또는 조정 유형, 상품, 창고, 수량, 사유
- 이동 이력: 일자, 유형, 상품, 창고, 수량, 단가, 금액, 원천문서, 처리자

## 4. 검증 기준

- SKU·창고코드·원천 이동 중복 차단
- 불합격 수량 미반영, 합격수량만 입고
- 음수재고 차단
- 출고 원가가 현재 이동평균 원가와 일치
- 새로고침 후 데이터 유지, 권한검사, 감사기록
- 안전재고·미반영 입고 알림 및 월마감 차단
- 전체 빌드와 회귀 테스트 통과

## 5. 후속 범위

로트·시리얼번호, 창고 간 이동, 실사 차이 결재, 반품, 납품 문서의 품목선 자동출고는 실제 상품코드·창고·시리얼 운영정책을 확인한 뒤 확장한다.
