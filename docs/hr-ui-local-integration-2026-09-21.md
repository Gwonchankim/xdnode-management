# HR·임금 UI 수정 및 로컬 연동 재검증

일자: 2026-09-21

## 사용자 확정 범위

- 기존 보고서 1·2번 인센티브 연결 개선: 제외. 인센티브는 직접 입력할 예정이므로 계산·가져오기 업무 규칙을 변경하지 않았다.
- 3번 UI 안정성·접근성: HR 및 임금 화면 수정 완료.
- 4번: 로컬 실행 기준. 배포 환경 정비와 저장소 전체 타입 설정 변경은 이번 범위에서 제외했다.
- 5번 설정 기능 추가: 보류. 기존 화면의 React 검사 오류만 정리했으며 새 설정 저장 기능은 만들지 않았다.
- 6번: 로컬 AI 실연동, 실패·재시도, 역할별 접근 검사 진행. 실제 마이크·운영 계정별 브라우저 로그인·장시간 부하는 아래 제한을 참조한다.

## UI 변경

1. HR 팝업의 공통 `HrModalBackdrop`을 추가했다. 팝업 이름, 닫기 버튼 이름, 처음 열었을 때 포커스, Tab/Shift+Tab 순환, Esc 닫기와 닫은 뒤 이전 요소로의 포커스 복귀를 통일했다. 내부 클릭이 배경 닫기로 전달되지 않도록 배경 자체를 누른 경우만 처리한다.
2. 퇴직 체크리스트 컴포넌트를 상위 함수 밖으로 분리했다. 체크할 때마다 입력 요소가 새로 만들어져 포커스가 사라지는 구조를 제거했다.
3. 직원 급여 기준 5개 금액 입력과 최종 처우 연봉 입력에 실제 label/input 연결을 추가했다. 직접 편집으로 전환한 금액 칸의 포커스는 명시적인 `focusOnEdit`으로 유지한다.
4. 처우 확정·거절 팝업의 접힌 헤더 상태는 팝업을 여는 이벤트에서 초기화한다. HR 외부 화면 이동 요청도 prop 변경을 확인하는 방식으로 처리한다.
5. 오늘 날짜는 한국 날짜 구독 훅으로 읽는다. 렌더 도중 Date.now를 직접 호출하던 곳을 정리하고 자정 또는 창 복귀 후 날짜 갱신을 지원한다.
6. 임금 설정은 클라이언트가 준비된 후 초기값으로 읽는다. 설정 복원용 연쇄 effect를 제거했다. 급여월을 불러오는 동안 이전 월의 표를 숨기고 편집을 차단하며, 저장 중에는 급여월 전환을 막는다.
7. 면담 녹음에 플레이어 이름과 펼쳐 볼 수 있는 전사문을 연결했다. 전사문이 없으면 입력/전사 필요를 안내한다. 수기 전사문에 임의의 자막 시간은 만들지 않았다.

전역 검사 규칙을 끄지 않았다. 세 가지 좁은 예외에는 코드에 이유를 명시했다: Shadow DOM 전용 CSS 링크, 팝업 컨테이너의 Escape/Tab 처리, 인접 전사문을 대체 텍스트로 제공하는 오디오 전용 플레이어. 전사문이 없는 기존 녹음의 내용까지 자동으로 보충한 것은 아니다.

## 실제 연동 결과

| 검사 | 결과 | 자료·저장 범위 |
|---|---|---|
| Claude 이력서 분석 | HTTP 200. 가상 지원자 이름·직무 추출, 미제공 생년월일은 빈 값 유지 | 가상 이력서만 전송. 실제 라우트 + 메모리 DB |
| Claude 임금 어시스턴트 | HTTP 200. 가상 지급액 100+200=300 답변, 변경 제안 0개 | 가상 JSON만 제공, 실제 로컬 브리지 3130 |
| Cloudflare 음성 전사 | HTTP 201 / COMPLETED. 합성한 한국어 문장과 일치하는 전사 반환 | Windows 합성 음성, 메모리 DB/R2. 실직원 녹음 미전송 |
| 현재 로컬 ERP의 전사 환경 반영 | 미존재 시험 녹음 요청에 404 반환 | 설정 미완료 503이 해소됨. 실제 녹음/직원 기록 생성 없음 |
| 로컬 브리지 상태 | 3110·3120·3130 health 정상 | Codex 브리지 3110은 상태 확인만; 생성 응답은 현재 Claude 경로에서 확인 |

전사 실패 원인은 `.env.local` 맨 앞의 UTF-8 BOM이었다. Vite 환경 로더가 첫 변수인 계정 ID를 읽지 못했다. **BOM만 제거했고 설정값과 토큰은 변경하지 않았다.** 이후 로컬 환경 로딩과 실제 전사 성공을 확인했다. 해당 파일은 기존처럼 Git 추적 대상이 아니다.

## 추가 회귀 검사

- `tests/hr-ai-integration.test.mjs`: 7개. 실제 전사 라우트/SQL을 실행하고 제공자 응답만 대체해 성공, 원문/검토본 분리, 재확정 거절, 한도 초과, 시간 초과, 빈/잘못된 응답, 명시적 재시도, 녹음 누락/10MB 초과, 이력서 응답 오류를 검사한다.
- `tests/hr-local-permissions.test.mjs`: 6개. SUPER_ADMIN, HR_ADMIN, RECRUITER, FINANCE_ADMIN, SALES_ADMIN, VIEWER별 직원·임금·채용 읽기/쓰기 및 결재 설정 접근을 검사한다. 실제 계정 권한은 수정하지 않는다.
- 기존 API 통합 검사 111개와 계산·결재·원장 회귀 검사도 전체 실행에 포함했다.

## 브라우저 확인

- 인사기록 팝업의 금액 label 5개가 해당 입력과 연결됨을 확인했다.
- 첫 닫기 버튼에서 Shift+Tab을 누르면 팝업 내 마지막 조작 요소로 이동했다.
- 퇴직 체크박스 변경 후에도 해당 INPUT에 포커스가 유지됐다. 저장하지 않고 Esc로 닫으면 이전 팝업의 퇴직 버튼에 포커스가 돌아왔다. 다시 열어 미저장 체크가 반영되지 않았음을 확인했다.
- 8월·9월 급여 전환과 저장된 명부 로딩을 확인했다. 로딩 중에는 이전 월 금액 표가 표시되지 않는다.
- 퇴직 정산/회수 영역의 기존 배치가 유지됨을 스크린샷으로 확인했다.
- 검사 중 새 업무 실행 오류는 관찰되지 않았다. HWP 브라우저 확장이 html 속성을 추가하며 발생하는 기존 hydration 경고는 남아 있다.

## 최종 결과와 제한

- `npm test`: 빌드 성공, **396개 통과 / 실패 0 / 생략 0**.
- 수정 대상 HR·임금·공통 UI·신규 검사 파일 ESLint: **오류 0 / 경고 0**.

- 인센티브 화면의 별도 React 상태 검사 2건은 이번 제외 범위로 유지했다. 전체 저장소 lint 통과를 의미하지 않는다.

- 운영 직원·지원자의 등록/삭제, 급여 확정, 실제 녹음 업로드, 커밋·배포는 하지 않았다.
